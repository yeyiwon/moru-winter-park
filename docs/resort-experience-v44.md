# v44 · 공동 체험, 개인 지식집, 모바일 화면 정리

작업일: 2026-11-19. 기존 겨울 공간과 브랜드 준비본 위에서 작업한다. 운영 중인 데이터·월드 배치·입장 정책을 새로 만드는 작업은 아니다. 현재 반영 대상은 실행 중인 개발 미리보기이며, 운영 배포 상태는 README와 DEPLOYMENT 기록을 별도로 따른다.

## 사용 경험의 기준

이 공간은 같은 곳에서 함께 볼 수 있는 체험과 혼자서도 남길 수 있는 발견을 함께 제공한다. 불꽃놀이는 한 번의 공유 공연, 퀴즈는 개인 기록, 료칸은 자리와 순서가 있는 작은 서비스로 구분한다. 일반 공지와 이벤트 편집·팝업은 제공하지 않는다. 불꽃놀이 시작 전에만 짧은 예고를 보여 준다.

## 불꽃놀이

유효한 방문 세션이면 설정의 불꽃놀이 신청 버튼을 사용할 수 있다. 서버는 10초 예고, 기존 74초 공연, 공연 종료 후 180초 대기를 계산한다. 동시에 들어온 신청은 조건부 UPSERT 하나로 같은 공연에 합친다. 요청이 많다고 공연이나 대기열을 방문자마다 추가하지 않는다.

관리자의 시작도 같은 대기 시간을 지키며 중지 권한은 관리자에게 남는다. 중지 후에도 이미 정해진 다음 신청 시각을 유지한다. revision과 시작 시각을 비교해 늦게 도착한 응답이 취소된 공연을 다시 시작하지 않도록 한다. 카메라를 강제로 돌리거나 이동시키지 않는다.

신청 UI는 기존 presence의 공연 상태를 사용하며 별도 주기적 HTTP 요청을 늘리지 않는다. 입장·탭 복귀 때 상태를 다시 확인한다. 편집·퀴즈·채팅 중에는 시작 예고를 가리고, 이미 지난 카운트다운을 다시 재생하지 않는다. 일반 이벤트 폴링과 버튼, 일반 공지 출력도 제거했다. 서버의 과거 이벤트·공지 자료는 삭제하지 않았다.

관련 파일: `server/fireworks.js`, `dist/firework-score.js`, `dist/winter-fireworks.js`, `dist/fireworks-request.js`, `dist/community-ui.js`, `dist/world-interactions.js`, `dist/world-settings.js`.

## 퀴즈와 내 지식집

별빛 만물관에서 또는 설정의 내 지식집에서 혼자 퀴즈를 시작할 수 있다. 화면 가운데 질문 하나를 보여 주고 선택한 답·정답·해설·출처를 이어서 확인한다. `body.inside-room #quick-quiz`의 오래된 하단 고정·모바일 52dvh 제한이 중앙 규칙을 덮어쓰던 원인을 제거했다. 실내·실외 모두 중앙 카드이며 짧은 가로 화면에서는 본문만 스크롤한다. 푼 문제, 맞힌 문제, 담은 지식으로 다시 읽고 다시 풀 수 있다.

기존 익명 세션을 사용하며 서버가 공개 문제은행으로 채점한다. 질문·해설·출처의 버전을 함께 저장해 나중에 문제를 수정해도 당시 기록은 남는다. 다른 사람의 기록을 읽거나 저장할 수 없다. 저장 실패는 브라우저에 임시 보관한 상태로 분명히 표시한다. 로그인 없는 익명 세션이므로 기기 변경이나 쿠키 삭제 뒤의 계정 복구는 제공하지 않는다.

자세한 API·보관·검증 계약: [개인 지식집](quiz-journal.md).

## 료칸의 서비스와 수족관

오마카세 카운터의 세 좌석 중 사용자가 고른 자리를 서버가 예약하고 셰프의 9초 서빙 구간을 순서대로 정한다. 대기 → 인사 → 준비 → 음식 운반 → 건네기 → 식사로 이어진다. 처음부터 모든 좌석에 놓여 있던 음식은 제거했다. 서빙 전에는 손님 손의 음식도 보이지 않는다. 자리에서 나오거나 예약이 끝나면 관련 상태를 정리한다. 이 버전은 한 접시를 대접하는 기본 흐름이며 여러 코스의 메뉴·대화 시스템은 포함하지 않는다.

기존 `ride_seats`에는 두 자리 제한이 있었으므로 `0016_dining_seats.sql`에서 모든 행을 보존한 채 dining에만 세 자리를 허용한다. 자세한 좌석·마이그레이션·테스트: [오마카세](ryokan-service.md).

수족관은 기존 메시 안에 시간에 따라 흐르는 광선, 수면선과 은빛 반짝임, 물고기 몸 굽힘을 넣었다. 세 무리가 완만하게 움직이고 방향 전환 속도를 제한한다. 수초와 기포도 같은 시간 기준을 사용한다. 실시간 유체 시뮬레이션이나 추가 반사 렌더 패스는 사용하지 않는다.

|---|---:|---:|
| Mesh 오브젝트 | 15 | 15 |
| Points 오브젝트 | 1 | 1 |
| 조명 | 1 | 1 |
| position attribute 정점 합계 | 23,921 | 23,921 |
| low / medium / high 물고기 | 12 / 24 / 32 | 12 / 24 / 32 |
| low / medium / high 기포 | 20 / 40 / 64 | 20 / 40 / 64 |

위 수치는 오브젝트·기하 집계이며 실제 draw call·GPU 시간 측정이 아니다. 새로운 셰이더 연산이 있으므로 FPS가 같거나 더 높다고 단정하지 않는다. 보이는 근거리 물고기의 행렬 갱신은 low 24Hz, medium/high 30Hz 이내이며 멀거나 화면 밖에서는 약 5Hz로 줄인다. 숨긴 공간과 움직임 감소 상태에서는 시계를 멈추고 복귀 시 누적 시간을 따라잡지 않는다.

### 원하는 자리와 실내 디테일

오마카세와 공유 벤치는 실제 의자 표면 또는 화면에 투영된 순서의 좌석 버튼으로 고른다. 이미 찬 자리는 선택할 수 없고, 동시 선택 경쟁에서도 다른 빈자리로 자동 배정하지 않는다. 동일 자리 재시도는 기존 예약을 반환한다. 기존 예약 해제를 기다린 뒤 새 예약을 보내며, 늦게 도착한 만료 응답이 새 좌석을 해제하지 않도록 세션·예약을 함께 비교한다. [좌석과 실내 시야](seating-and-indoor-view-v44.md).

료칸은 높은 목재 격자 천장, 회벽과 장지, 간접 발광, 둥근 오마카세 상판, 주방 선반, 휴식 벤치의 쿠션, 창가 풍경과 연속된 족욕 석재 테두리를 보강했다. 추가 가구 디테일은 기존 경계 안에 두고 입구에서 각 체험까지 통로를 유지한다. 높은 천장에 맞춰 벽 윗부분도 닫았다. [료칸 제작 기록](ryokan-craft-v44.md).

천문대는 과학·자연·역사·논리 4개 전시관과 중앙 천체 기구를 유지하며 곡면 유리 캐비닛, 브라스 장식, 표본·책·도자기, 돔 별자리와 바닥 나침반을 추가했다. 전시 기둥이 통로 밖으로 뻗던 범위를 정리하고 실제 전시 모델을 기존 반경 2.4m, 중앙 기구를 4.2m 안에 넣었다. 전시에서 기존 퀴즈·퍼즐을 여는 흐름을 유지한다. [천문대 제작 기록](museum-interior-v44.md).

## 화면과 입력

- 커마 닉네임은 프리뷰 위에 작은 글씨로 표시하고 누르면 편집한다. 불필요한 프리뷰 제목과 정면 버튼은 제거했다.
- 모바일 커마는 닉네임·프리뷰, 선택 목록, 저장 행을 분리한다. 선택 목록만 스크롤하며 저장 버튼은 별도 영역을 유지한다.
- 점프는 64px, 달리기는 48px이다. 지도는 조이스틱 위에 둔다. 음악 옵션의 글씨는 줄이되 터치 높이는 유지한다.
- 시설 이용 버튼과 종료 버튼의 정렬을 통일하고 모바일에서 키보드 힌트의 빈 자리까지 제거한다.
- 모달은 한 번에 하나가 입력을 소유한다. 소원 목록 같은 비모달은 위치와 스크롤을 보존하고 모달이 열린 동안 가린다. 대화창을 열었다고 탑승이나 식사를 종료하지 않는다.
- 닫기 애니메이션 중 다시 연 패널이 이전 Promise에 의해 닫히던 경쟁 상태를 수정했다.
- 관리 목록의 제목·본문·보조 정보·상태 글씨 크기를 분리했다. 불꽃 상태는 제목 옆에 놓고 일반 결과 메시지와 분리한다.
- 마이크 모듈 로딩과 사용자용 성능 확인 UI는 제거했다. 내부 측정 도구는 유지했다.
- WebGL을 만들 수 없는 경우 로딩 오류 화면이 설정·퀴즈 버튼의 포인터 입력까지 가로막지 않게 했다.

## 카메라와 밝은 유리 UI

같은 작업 중 추가된 고정 기본 시점·명시적 시야 조절·트리 거리·높고 넓은 실내 시야는 [카메라 정책](stable-camera-v44.md)에 기록한다. 임의 자동 연출을 부드럽게 보간하는 데 그치지 않고 카메라 상태를 쓰는 경로를 통합한다.

실외 기본은 pitch 0.48·거리 16.5·FOV 50, 실내 첫 방문은 pitch 0.65·거리 15·FOV 50이다. 일반 이동·점프·마우스 이동은 시야를 재설정하지 않는다. `시야 조절` 또는 PC 마우스 오른쪽 드래그로 바꾸며 조절을 끝내도 선택한 각도를 유지한다. 방별 시야와 실외 복귀 시야를 기억한다. 료칸의 완성 모델과 실제 카메라 가림 계산에서 입장 거리 15.000m, 식사 좌석 14.921m와 pitch 0.650rad를 확인했다. 이는 기하·정책 검증이며 실제 화면의 멀미 여부 검증은 아니다.

설정·커마·지도·채팅·관리·퀴즈·이용 안내를 `ui-system.css`의 공통 토큰으로 정리했다. 첫 밝은 표면은 흰색 alpha 84~90% 때문에 불투명한 카드처럼 보였고, 후속 피드백에 따라 alpha 10~22%의 얇은 글래스·밝은 글자·빛 테두리로 다시 조정했다. 선택지 채움도 5.5%로 낮추고 하단 막대를 투명하게 했다. 겨울밤 월드의 밝기는 바꾸지 않는다.

blur는 PC10px·모바일8px·low4px이며 일반 버튼에는 중첩하지 않는다. 열린 드롭다운 하나만 뒤의 글자와 구분하기 위한 국소 blur를 허용한다. 그래픽 품질 때문에 불투명 표면으로 바뀌지 않으며, 투명도 감소 설정과 blur 미지원 환경에는 읽기 쉬운 밝은 표면·짙은 글자 대체를 둔다. [투명 글래스 후속과 실제 캡처](clear-glass-v44.md).

## 확인한 것과 남은 것

격리된 SQLite로 서버 검증을 수행한다. 새 게스트·초대·공연·퀴즈 기록은 운영 DB에 만들지 않는다. 기존 사용자 개발 DB와 별도의 QA 데이터베이스에서 실제 입장과 API 연결을 확인한다.

브라우저에서 퀴즈 정답 제출 → 해설/출처 → 서버 저장 확인 → 지식 담기 → 목록에서 다시 읽기를 확인했다. 390×844, 320×640, 844×390의 실제 CSS viewport에서 커마의 미리보기·선택 영역·저장 행이 겹치지 않는지 확인했다. 이는 iframe을 이용한 레이아웃 검사이며 실물 휴대폰의 터치·키보드·발열·성능 검증이 아니다.

최종 전체 자동 검사는 448/448 통과했다. 실제 CSS와 퀴즈 컴포넌트로 실내 상태를 재현해 390×844·320×640·844×390 모두 중앙 정렬, 가로 화면 본문 스크롤과 고정된 제목·닫기 영역을 확인했다. 별도 시험 페이지는 배포 디렉터리에서 제거했고 증거만 [브라우저 검사 기록](../qa/resort-v44/browser-checks.json)에 보관한다. 빌드·용량 결과는 [검증 기록](TESTING.md)을 따른다.

현재 검증 브라우저는 `GL_RENDERER = Disabled`로 WebGL context를 만들 수 없다. 따라서 3D 카메라의 최종 감각, 셰프와 물 표현의 런타임 육안 확인, 셰이더 GPU 컴파일, Windows/iPhone/Android 실제 FPS는 UNKNOWN이다. 테스트 통과나 오브젝트 수 유지로 이 항목을 검증 완료로 표시하지 않는다.
