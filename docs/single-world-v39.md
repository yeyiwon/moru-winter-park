# v39 단일 월드와 초대 기반 접속

## 기존 문제

기존 `/api/join`은 `winter-plaza`에 초대 없이 입장할 수 있었고, `/api/invite`는 비밀번호로 보호된 별도 `invite_rooms`를 만들었다. 관리자가 초대를 만들면 본인도 다른 방으로 이동했기 때문에 일반 링크 방문자와 만나지 못했다.

## 변경한 계약

- 서버의 모든 입장은 `winter-plaza` 한 곳으로 고정한다. 클라이언트의 임의 room ID는 거절하고 정원 초과 시 다른 방을 생성하지 않는다.
- `world_invites`: CSPRNG 256-bit 토큰의 SHA-256 해시, ID, 생성/만료/폐기 시각만 저장한다. 원문 토큰은 생성 응답에서 한 번만 제공한다.
- 링크는 `/#invite=...` 형태다. URL fragment는 서버 access log/Referer에 전송되지 않는다. 클라이언트는 즉시 주소에서 제거하고, `invite-check`와 첫 `join`에만 전달한다. 이후 위치/채팅/게임 요청에는 HttpOnly 게스트 쿠키만 사용한다.
- 기존 탭에서 fragment만 바뀌는 탐색도 다시 검증한다. 원문은 localStorage에 저장하지 않는다.
- 관리자는 기존 Sites 인증 ID로 서버에서 확인한다. 최초 소유자 바인딩에는 기존 `OWNER_EMAIL` 정책을 사용하고 이미 바인딩된 ID는 바꾸지 않는다. Vercel 프록시는 외부에서 보낸 관리자 identity header를 전달하지 않는다.
- Vercel의 관리자 로그인은 기존처럼 Sites 인증 주소로 연결된다. 관리자 화면과 Vercel 게스트 화면은 같은 DB/월드를 사용한다.
- 초대 유효기간은 1/7/30일, 기본 7일이다. 서로 다른 유효 초대 링크도 같은 월드에 입장한다.
- 링크 폐기는 그 링크에 연결된 기존 세션도 즉시 무효화하고 좌석을 해제한다. 다음 통신에서 클라이언트는 이동/체험을 종료하고 입장 화면으로 돌아온다.
- 강퇴는 현재 접속 권한을 취소한다. 해당 게스트는 강퇴 이후 발급된 새로운 초대가 있어야 재입장한다. 차단은 같은 익명 게스트 세션에 대해 새 초대로도 입장할 수 없게 한다. 관리자 자신은 차단/강퇴할 수 없다.
- 익명 정책상 쿠키 삭제·다른 브라우저를 사용하면 다른 게스트가 된다. 실명/계정 기반 영구 인물 차단이라고 주장하지 않는다. 링크 유출 시 해당 링크 폐기와 새 링크 공유를 사용한다.

## 데이터 보존

`0011_busy_hawkeye.sql`은 `world_invites`와 visitors의 입장 승인 필드만 추가한다. 기존 방문자 외형, 소원, 트리 장식, 기존 방 테이블을 삭제하지 않는다. 이전 공개 접속 세션은 자동 승인하지 않으며, 새 초대로 검증하면 기존 쿠키 ID와 외형·장식 소유권을 유지한다.

기존 메인 월드의 소원·장식은 그대로 공유한다. 이전 비밀번호 방 자료는 DB에 보존하지만 새 메인 월드로 무단 공개·병합하지 않는다. 기존 `?room=` 링크는 폐기된 방식으로 안내한다. 신규 독립 방은 만들 수 없다.

위치/현재 체험/말풍선은 일시 상태, 소원·트리 장식은 영속 상태다. 기존 D1 저장, 30일 게스트 보존, 10분 말풍선 정리, 좌석 만료를 유지한다. 브라우저 종료만으로 게스트 레코드를 삭제하지 않는다.

## 수정 파일과 성능

`server/invitations.js`는 초대 발급·해시 검증·세션 승인·단일 입장을 담당한다. `server/api.js`는 모든 보호 API 앞에서 승인된 세션을 확인한다. `server/community-api.js`는 강퇴/차단 시 좌석을 정리한다. `server/vercel-proxy.js`는 검증 경로만 추가하며 관리자 인증 전달을 허용하지 않는다.

`dist/social.js`, `space-links.js`, `index.html`, `community-ui.js`는 기존 유리 UI에 초대 검증·닉네임/색 선택·만료기간·폐기 목록을 연결한다. `park.js`는 입장 전/권한 취소 시 조작을 중지한다. 월드 좌표·지형·시설·VFX는 변경하지 않는다.

토큰 검증은 SHA-256과 인덱스 조회이며 기존 PBKDF2 비밀번호 검증을 반복하지 않는다. 세션 확인은 방문자/초대/차단을 한 DB 조회로 확인한다. 초대/입장 rate limit, 원자적인 최대 12명 조건, 기존 위치/채팅/소원 입력 검증을 유지한다. 새로운 렌더러·서버·production dependency는 추가하지 않는다. 렌더 성능 변화는 측정 전 UNKNOWN이다.

## 검증 상태

자동 검사 368/368, 두 배포 build 및 용량 검사 PASS. `scripts/verify-single-world-v39.mjs`로 독립된 PC/모바일 크기 Chrome에서 11개 묶음 검사 PASS, page 오류 0. 이동·채팅·소원·외형/재접속·시설 출입·음악과 강퇴/차단/초대 폐기를 확인했다. 테스트 DB는 `/tmp/winter-v39-invites.sqlite`로 운영과 분리했다.

실행: 로컬 guest 4187과 `LOCAL_OWNER_EMAIL=qa-owner@example.test`를 사용하는 로컬 owner 4188을 같은 테스트 DB로 실행한 뒤 위 스크립트를 실행한다. 실제 production은 해당 환경변수를 사용하지 않으며 Sites 인증으로만 소유자를 확인한다.

검증 중 같은 탭의 새 초대 fragment가 재초기화되지 않는 문제를 발견해 `hashchange` 재검증과 회귀 검사를 추가했다. 초대 취소 때 탑승·카메라·트리 체험까지 종료한다. 입장 안내는 기존 유리 패널을 사용하며 내용 크기에 맞게 줄였다. 기존 사용자 설정 패널의 크기/색은 바꾸지 않았다.
