# v35 — 공통 UI 및 선택적 AI 인터랙션

2026-11-18. 기준 코드 `18a79b43c1e43a0d77fc40495cef286100ac3a5a`.

**상태: 로컬 구현과 자동 검사 완료. 실제 브라우저·라이브 AI·마이크 검증 및 운영 배포 미완료.**

브라우저 실행을 요청했으나 자동 승인 검토 시스템의 사용량 한도 오류로 실행되지 않았다. 안전성 판단에 따른 거절은 아니다. 다른 실행 경로로 이를 우회하지 않았다. 이번 변경의 전후 스크린샷, 프레임 측정, 실제 기기 검증 결과는 없다.

## 현재 구조와 선택 이유

- React 앱이 아니라 Three.js + ES modules + DOM UI다. React 또는 추가 UI 프레임워크를 도입하지 않는다.
- `glass.css`에 화면별 색상·블러·포커스·선택 스타일이 반복되어 있고 기본 블러가 30px이었다. 공통 토큰과 표면 규칙을 마지막 테마 레이어 `ui-system.css`에 모았다. 기존 레이아웃·지도·캐릭터 선택 로직은 유지한다.
- 기존 서버의 `/api/assist`는 선택적 해설·장식 추천이었다. 음악/전시 선택은 새 `/api/experience`로 분리하고 기존 익명 세션·동일 출처 검사 뒤에 배치한다.
- 기존 v33/v34의 목재·다다미·자연석·수면·수족관과 온천 입퇴장을 재사용한다. 이번에 다시 모델을 교체하거나 시설을 늘리지 않는다.
- 이미 제거한 아이스링크를 예시 문구 때문에 다시 만들지 않는다.

## UI와 접근성

`ui-system.css`의 공통 토큰: 색상, 유리 표면, 텍스트, 필드, 테두리, 반경, 4/8/12/16/24px 간격, 44px 기본 컨트롤, 140/180ms 전환, 도크/선택 목록 레이어. 기존 설정 프레임 크기와 커마 미리보기 배치는 유지한다.

패널 내부 버튼·필드에 중복 블러를 적용하지 않고 모달 배경 블러를 제거한다. 모바일 채팅과 소원 목록은 추가 블러를 사용하지 않는다. `prefers-reduced-transparency` 또는 backdrop-filter 미지원 시 더 불투명한 대체 표면을 사용한다. 텍스트 대비는 어두운 일정 표면에 맞춰 설계했으나 실제 밝은 월드 위의 픽셀 대비와 실물 폰트 렌더링은 **미검증**이다.

기존 '움직임 줄이기'는 UI 전환에도 적용한다. 새 '번쩍임 줄이기'는 퀴즈 폭죽·정오답 펄스를 억제하고 파티클 밝기를 낮춘다. 이동 트레일과 기본 겨울 조명은 유지한다.

## 음악 추천

설정 → 소리 → 추천 및 접근성:

1. 기본 꺼짐인 'AI 추천 사용'을 직접 켠다. 화면에 전송 범위를 명시한다.
2. 왈츠·발레 / 재즈 / 피아노 / 시네마틱, 잔잔함 / 조금 경쾌함을 직접 고른다.
3. '음악 추천'을 눌러야 서버에 요청한다. 설정 변경·페이지 진입만으로 호출하지 않는다.
4. 기존 11곡 중 최대 3개를 카드로 보여준다. 제작자·곡명은 원본 카탈로그에서 가져온다.
5. 재생을 눌러야 기존 플레이어가 곡을 바꾼다. 크로스페이드·음소거·셔플·이전/다음 로직을 유지한다.

스타일 분류는 이 앱의 편집 메타데이터이며 음원의 공식 장르나 사용자의 심리 진단이 아니다. 실패/한도/미설정일 때 등록된 곡의 결정적 기본 추천임을 표시한다. AI 결과를 가장하지 않는다.

## 상황형 전시 카드

천문대의 기존 전시 상호작용에 '전시 보기'를 연결했다. 기본 상태에서는 출처가 있는 기존 콘텐츠와 관리자 검토 내용을 사용한다. 기존 '퀴즈'와 논리 퍼즐은 유지한다.

- '다른 주제'는 로컬 콘텐츠를 순환한다. AI 호출 없음.
- 'AI 전시 조합'은 동의한 사용자 요청에만 실행한다.
- 서버는 활성화된 해당 전시 분야의 후보를 구성하고 모델에 ID·주제·문제 제목만 보낸다.
- 모델은 후보 ID와 `ExplanationPanel` 또는 `QuizCard`만 반환한다.
- 사실·해설·정답·출처는 서버가 이미 가진 검토된 원문으로 해결한다. 생성 문장을 사실처럼 검증 없이 표시하지 않는다.
- 카드의 문제 풀기는 그 카드의 실제 question ID로 기존 퀴즈를 연다.
- 카드 개방은 해당 전시물의 기존 조명을 반응시킬 뿐 카메라를 강제로 회전·확대하지 않는다.

## 동의·개인정보·비용

- 선호도는 `winter-preferences-v1`로 이 브라우저에 저장한다. DB에 선호도나 사용자 행동 이력을 새로 저장하지 않는다.
- 새 API 입력은 `kind`, `consent`, `style`, `pace`, `gallery`만 허용한다. 임의 채팅·소원·사용자 식별 필드가 추가되면 거절한다.
- 새 추천 API에서 외부에 보내는 값은 명시적 선택과 카탈로그다. 닉네임·방 ID·이동·성격·심리 정보는 보내지 않는다.
- 기존 소원 장식 추천은 소원 본문을 보내므로 이를 따로 명시하고 같은 AI 동의 설정을 적용했다. 기존 해설 API도 `consent:true`를 요구한다.
- 동의를 끄거나 패널을 닫으면 클라이언트 요청을 취소하고 늦은 응답이 UI에 다시 나타나지 않도록 처리한다. 이미 서버/제공자에서 처리한 호출 비용까지 취소한다고 보장하지 않는다.
- Responses API의 `store:false` 사용. 이는 제공자의 모든 보관 정책이 사라진다는 뜻이 아니다. 앱 DB에 AI 요청 본문을 기록하지 않는다.
- 분당 새 추천 요청 4회. 기존 AI와 공유하는 하루 사용자 20회 / 서버 100회 한도. 메모리 캐시 최대 100개·5분, 동일 요청 진행 중 합치기.
- 최대 출력 512 tokens, 호출 timeout 8초, 입력 본문 최대 600자. 실제 모델은 기존 서버 `OPENAI_MODEL`을 사용한다. 새 키나 모델로 임의 변경하지 않았다.
- 모의 공급자 테스트의 token 수를 실제 과금으로 보고하지 않는다. 이번 작업의 라이브 AI 토큰·응답 지연·실제 요금은 **UNKNOWN**이다.

설정 지우기는 개인 선호도만 초기화한다. 기존 닉네임·소원·커마·오디오 상태를 삭제하지 않는다. 공개 콘텐츠 신고와 관리자 권한 검사는 기존 서버를 유지한다.

## 선택적 음성 입력

안전한 연결과 `SpeechRecognition` 또는 `webkitSpeechRecognition`이 있는 브라우저에서만 활성화된다. 별도 동의 체크와 '마이크 시작'을 누른 뒤 최대 8초 동안 한 명령만 받는다. 패널 닫기·탭 숨김·페이지 종료·중지·오류에 recognition을 정리한다. 자동 재시작은 없다.

지원 명령은 고정된 한국어 목록으로 제한한다. 녹음과 인식 문장을 앱에 저장하거나 OpenAI로 보내지 않는다. 브라우저의 음성 인식 제공자가 서버에서 처리할 수 있음을 시작 전에 표시한다. 미지원·거부·인식 실패 시 기존 버튼과 키보드를 계속 쓸 수 있다.

실제 마이크 권한 요청 및 실제 한국어 인식 성공률은 **미검증**이다. 테스트는 가짜 recognition 객체의 시작·중복 입력·거부·종료 수명만 검증했다.

## EEG 연구 계획 (미구현)

호환 장치, 실제 센서 신호·단위·sampling rate, 장치별 품질 기준, 목적별 명시적 동의, 삭제/중단 절차가 먼저 필요하다. 실험 시에도 원시 신호를 기본 서버 저장하지 않으며 로컬 처리와 센서 미연결 fallback을 우선한다. 검증된 프로토콜과 비교 조건 없이 감정/집중도 라벨을 생성하지 않는다. 마우스·스크롤·클릭 빈도로 이를 대체하지 않는다. 현재 UI에 EEG 토글이나 가짜 연결 상태를 만들지 않았다.

## 검증 및 남은 항목

- 전체 자동 검사 **330/330 통과**. 결과는 `qa/browser-v35/local-verification.json` 참조.
- Sites Worker / Vercel 정적 빌드와 크기 예산: 같은 파일에 실제 결과 기록.
- 서버 동의·세션·허용 필드·응답 schema·위조 ID·중복 ID·미설정·거부·timeout·한도·캐시/동시 호출 합치기 검사.
- DOM에서 기본 꺼짐, 요청 전 호출 0회, 수동 재생, 설정 초기화, 동의 철회/패널 종료 시 취소, 전시 카드→해당 퀴즈, 미지원 음성 입력 검사.
- 기존 월드/입퇴장/온천/수족관/멀티플레이 회귀는 기존 자동 검사에 포함. 이는 실제 GPU 브라우저 플레이 확인을 대체하지 않는다.
- `scripts/verify-ui-v35.mjs`에 PC·모바일·작은 화면·가로 화면·전후 캡처·패널 열기 전후 RAF/CDP 측정 절차를 준비했다. **구문 검사만 통과, 실제 실행하지 못함**.
- 해당 브라우저 스크립트도 AI 응답을 모의한다. 별도의 라이브 모델 결과 확인, 실제 마이크, 실물 모바일 검증이 남는다.
- 실제 전후 스크린샷·FPS·프레임 타임·GPU 비용 없음. 블러 수치 감소를 측정된 성능 개선율로 주장하지 않는다.
- **운영 사이트는 v34 유지. GitHub push와 Sites/Vercel v35 배포 미완료.**

재개 순서: 별도 QA DB 서버 → 기준 revision 캡처 → 수정본 UI·카메라·실제 온천 회귀 → 측정 비교 → 라이브 AI 1회와 실패 동작 → 필요 수정 → 두 운영 사이트 배포 및 실제 파일 확인.
