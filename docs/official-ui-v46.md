# v46 공식 주소·모바일 조작 안정화 — 2026-11-19

현재 작업 상태: 로컬 회귀 및 별도 Cloudflare 서버 사전 검증 완료. 운영 전환 결과는 별도 배포 기록으로 구분한다.

- 공식 사용자 주소는 `https://moru-winter-park.vercel.app/`, 관리자 진입은 `/admin`. Sites는 기존 DB·API·소유자 인증을 유지한다. 실제 소유자 인증 왕복을 확인하기 전까지 기존 Sites 로그인 경로를 삭제하거나 강제 리다이렉트하지 않는다.
- 사용자가 새 고정비를 거절하여 Render 서버는 만들지 않는다. 이후 사용자가 새 Cloudflare 계정을 준비했다. 무료 플랜 연결·검증·전환 전까지 기존 HTTP 연결과 **동시 접속 12명**을 유지한다. 저장소의 별도 실시간 Worker 구현과 로컬 100명 검증을 운영 수용량으로 표시하지 않는다.
- 모바일 조이스틱의 원은 고정하고 손잡이만 움직인다. 전체 반경·원 밖 입력·대각선 정규화·달리기/카메라 조작은 유지한다.
- 커마의 복실함 조절만 제거한다. 몸통·털·꼬리의 외형/저장 데이터는 유지한다. 모바일 미리보기 확대, 닉네임 입력 영역, 낮은 대비 스크롤바, 채팅 44px 터치 영역을 정리한다.
- 트리/벤치 안내는 근접 우선순위와 이탈 여유를 적용한다. 좌석은 별도 선택 화면 없이 서버가 빈 좌석을 원자적으로 배정한다.
- 트리 전체와 상단이 보이는 임시 시야를 적용하고 닫을 때 이전 시야로 복귀한다. 직접 조작은 자동 시야보다 우선한다. 수동 시야는 하늘을 볼 수 있다.
- 기존 트리 가지의 클릭 대상 누락을 복구했다. 소원 목록은 실제 장식 Geometry와 기존 월드 renderer로 한 프레임에 하나씩 썸네일을 만들고 최대 64개를 캐시한다. 추가 WebGL renderer는 없다.
- 30초 초기화 지연 안내 후 실제 준비가 완료돼도 입력을 가리던 로딩 오류를 복구했다. 실제 초기화 예외는 재시도를 유지한다.
- 폐기된 햄버거 메뉴를 참조하여 채팅이 열리지 않던 오류를 제거했다. 채팅을 여는 동안 주변 조작 아이콘을 숨기고 닫힘 애니메이션 후 복구한다.
- 배포 자산을 하나의 검증된 캐시 묶음으로 설치한다. 살아 있는 탭 중간에 다른 릴리스의 모듈을 섞지 않는다. `/admin/`에서도 루트 기준 자산을 불러온다.

## 배포 환경 검사 보강

Vercel의 Git 아카이브 빌드에는 `.git`이 없으므로 검증된 `VERCEL_GIT_COMMIT_SHA`를 사용하고, 로컬에서는 Git HEAD와 dirty 상태를 기록한다. 별도 테스트를 포함한 전체 488개 자동 검사는 원격에서도 통과했다.

Linux CI의 브라우저는 하드웨어 GPU가 없다. Mac에서 SwiftShader로 재현한 모바일 화면은 scene 생성 35.084초, 첫 프레임 64.374초, 로딩 숨김 64.625초였다. 실제 초기화 완료와 지연 안내 복구는 정상이며, `world-ready` 후 추가 30초만 기다리던 검사 제한을 첫 GPU 프레임에도 기존 초기 진입 한도 120초로 적용했다. 검사 조건을 생략하거나 게임 품질을 낮추지 않았으며, 각 진입 시간과 오류 상태를 별도 출력한다. 소프트웨어 렌더러 수치는 실제 모바일 성능 수치가 아니다.

동일 CI 재실행에서 PC 22.930초/모바일 화면 85.704초 후 로딩 종료를 확인했다. 이어진 조이스틱 검사는 고정 700ms 동안 이동한 뒤 최대 속도를 요구하여 소프트웨어 렌더러의 적은 시뮬레이션 프레임에서 실패했다. 실제 가속된 속도와 손을 뗀 뒤 정지 상태를 기다리고 같은 속도 상한을 검사하도록 수정했다. 게임의 가속·입력·화질 설정은 변경하지 않는다.

원격 검사에서 확인한 하차 경쟁 조건도 수정했다. 이미 전송 중인 탑승 pose보다 좌석 DELETE가 먼저 처리되면 409가 발생할 수 있었다. 동일 상황을 재현한 자동 검사가 수정 전 실패/수정 후 통과함을 확인했다. `releaseRide`는 진행 중인 pose 응답을 기다리고 중복 해제를 합치며, 해제 동안 새 checkpoint를 보류한 뒤 일반 위치 전송을 재개한다. 잠든 기기의 좌석 만료 복구 검사도 함께 통과했다. 숨겨진 탭의 네트워크 확인은 RAF 대신 시간 기반 polling을 사용하고, 채팅은 짧게 사라지는 말풍선 대신 열린 채팅 기록에서 검사한다. CI는 설치된 Chrome이 있으면 재사용하며 없으면 기존 Playwright 설치를 유지한다.

GPU가 없는 CI에서 기본 화질은 한 프레임의 처리로 버튼 클릭 자체가 30초 이상 막혔다(모바일 첫 화면 141.331초). CI의 기능 회귀는 기존 사용자 선택지인 `low` 모드로 실행하고 실제 렌더링·입력·동기화 조건은 유지한다. 로컬 Mac GPU에서는 기본 auto 화질로 17/17, 오류 0을 별도로 확인했다(최종 세 진입 4.357/4.314/4.314초). 이는 CI 처리 속도를 실제 기기 성능으로 간주하거나 운영 기본 화질을 바꾸는 조치가 아니다. HTTP 실패 시 코드도 진단에 기록한다.

별도 headless 브라우저 context는 `bringToFront()`를 호출해도 둘 다 `document.hidden=false`임을 실제 확인했다. GPU 없는 CI에서 두 월드가 동시에 렌더링하며 초기화/클릭을 지연했다. CI는 비활성 클라이언트의 실제 지도 설정을 열어 월드 렌더만 일시 정지하고 WebSocket 연결은 유지한다. 조작 대상은 설정을 닫아 실제 월드 프레임·입력·시설을 검증한다. 로컬 기본 화질 다중 렌더 검사는 계속 별도로 유지한다.
