# v28 — 초대 공간과 접속 주소

## 확인한 원인

- Vercel의 `/api/*`는 Sites Worker와 같은 D1 DB를 사용한다. 두 서버로 데이터가 분리된 상태는 아니다.
- 기존 초대 화면은 새 방을 만든 뒤 숨겨진 별도 입장 버튼까지 눌러야 관리자가 이동했다. 손님은 초대 방, 관리자는 광장에 남을 수 있었다.
- 초대 링크를 백엔드 요청의 origin으로 생성하여 `chatgpt.site` 주소가 나왔다.
- 저장된 초대 방 세션을 복원해도 주소는 `/`에 남았다. 이 주소를 전달하면 상대는 광장에 입장했다.

## 변경

- 공유 링크는 `https://moru-winter-park.vercel.app/?room=…`로 생성한다.
- 관리자가 초대 방에 입장한 뒤 링크를 공개한다. 연결 실패 시 같은 초대 방으로 재시도한다.
- 현재 방을 주소에 반영하고, 새로고침 후에도 링크 복사를 제공한다. 새 초대 생성 버튼은 기존 방과 다른 방을 만든다는 명칭을 쓴다.
- 관리자 로그인 왕복에서 방 정보를 유지한다. 관리자 인증은 기존 Sites 로그인을 유지하며 Vercel의 게스트에게 관리자 권한을 부여하지 않는다.
- 방 이동 중 위치 동기화를 잠시 중단한다. 이전 방의 온라인 상태·탑승 좌석·클라이언트 채팅을 정리한다.
- Vercel에는 게임 세션 쿠키만 전달하고 호스팅 시스템의 별도 쿠키는 전달하지 않는다.

## 검증

- 수정 전 운영 서버에서 Vercel 접속자와 Sites 접속자의 동일 광장 내 양방향 위치 전달을 확인했다.
- 회귀 검사 27개 통과: 초대 생성 후 자동 입장, 실패 재시도, 새로고침, 로그인 복귀 주소, 서로 다른 origin의 초대 방 입장·이동·채팅, 공개 광장과의 분리, 세션 쿠키, 기존 공동 탑승 및 커뮤니티 동작.
- 초대 방 통합 검사는 격리된 SQLite DB와 실제 API·proxy 코드로 수행했다. 운영 관리자 로그인과 3D 화면의 두 브라우저 동시 플레이는 자동 조작 환경이 없어 확인하지 못했다.

## 이용 흐름

관리자는 로그인 후 초대에서 비밀번호를 정한다. 초대 방에 자동 입장한 다음 현재 링크를 복사해 전달한다. 손님은 그 링크에서 닉네임과 비밀번호를 입력한다. 같은 사람들을 초대할 때는 새 방을 만들지 말고 현재 방 링크를 복사한다.

Vercel은 화면과 API 중계, Sites Worker 및 D1은 공동 상태 저장을 맡는다. 기존 Sites 주소로 접속한 관리자와 Vercel로 접속한 손님도 같은 `room`이면 같은 공간을 사용한다.
