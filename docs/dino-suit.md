# DINO 공룡 후드 슈트 (첫 품질 검증 의상)

상태: v66으로 운영 배포(사용자 지시, 2026-11-25). 원단 질감과 후드 형태는 아래 한계대로 추가 개선 대상.

## 왜 바꿨나
구·원뿔·원판을 코드로 조합한 의상(오로라 망토, 별자리 망토, 아틀리에 베레모, 공룡 후드 1차)은 봉제 의상으로 보이지 않아 승인되지 않았다. 수치 조정으로는 해결되지 않는다고 판단해 절차형 의상 4종을 모두 빼고, 공룡 의상 하나만 실제 에셋 방식으로 다시 만들었다.

## 제작 방식
- `scripts/assets/dino-suit.py` (Blender `bpy` 5.3 + numpy, 오프라인 도구. 게임 의존성 아님)
- 후드 캡, 얼굴 둘레 패딩 프레임, 몸통, 꼬리, 이빨 7개, 등 가시 5개, 꼬리 가시 2개를 각각 UV를 가진 로우폴리 패치로 만든다.
- 같은 패치의 고밀도 메시(약 110만 정점)에 천 요철, 목·밑단 개더 주름, 중앙 봉제선, 스티치, 배 패널 퀼팅, 구름 패치를 넣고 Cycles로 오브젝트 스페이스 노멀, 색, AO를 굽는다.
- 결과물: `dist/dino-suit-mesh.js`(16비트 양자화, 슈트 3,234 정점 / 5,616 삼각형, 꼬리 302 / 488), `dist/textures/dino-suit-color.webp`(1024², 색×AO), `dist/textures/dino-suit-normal.webp`(2048²).
- 재생성: `DINO_SIZE=2048 DINO_SAMPLES=48 python3 scripts/assets/dino-suit.py -- <출력 폴더>` 후 세 파일을 위 경로로 복사.

## 게임 적용
- `dist/winter-couture.js`: 메시를 풀어 한 개의 공유 지오메트리·재질로 쓴다. 재질은 캐릭터 몸과 같은 벨벳 조명 방식(넓은 sheen, 약한 자체광)에 미세 결과 절제된 림을 더했다. 꼬리는 스프링으로 흔들린다.
- `dist/companion.js`: 슈트 아래 털은 짧게 눕히고, 후드를 쓰면 기존 꼬리·귀 머리띠를 숨긴다. 온천에서는 숨기고 료칸 유카타가 대신한다.
- `dist/wardrobe.js`: 머리 장식에 `dino-hood` 추가(무작위 외형에서는 제외).
- 캐릭터 메시 수 상한 테스트를 88 → 90으로 올렸다(슈트 1 + 꼬리 1). 입지 않으면 그리지 않는다.

## 실제 확인한 것
- 게임 안 정면·45°·측면·후면·클로즈업·플레이 카메라 캡처(헤드리스 Chrome, 소프트웨어 렌더러).
- `npm test` 596개 통과, `npm run check` 통과. `npm run test:budget`는 새로 빌드한 산출물 기준 통과(codeGzipBytes 1,256,716 / 1,280,000, coreBytes 37,636,256 / 37,748,736 — 남은 여유 약 110KB).
- 첫 배포(`99d9e7e`)는 CI 용량 검사에서 실패했다(codeGzipBytes 1,291,918). 로컬에서 이전 빌드 산출물로 검사해 통과로 잘못 판단한 것이 원인. 게임 메시 밀도를 낮추고 후드 가장자리를 얼굴 테두리 아래로 넣어 수정했다.

## 알려진 한계
- 레퍼런스 대비: 원단의 엠보 자카드 무늬와 털 결이 없다(표면이 매끈한 플러시). 위턱이 얼굴 위로 튀어나오는 주둥이 형태와 콧구멍, 팔 소매가 없다. 캐릭터가 공 하나라 머리·몸 구분은 목 개더선으로만 표현된다.
- 배 패널은 얼굴 아래 좁은 영역이라 플레이 카메라에서는 거의 보이지 않는다.
- 실제 GPU·모바일 FPS: UNKNOWN (미측정).
- 프런트엔드 캐시가 예전 버전인 방문자에게는 후드가 보이지 않는다(`/refresh.html`로 갱신).
- 털 길이 100에서 후드를 입으면 99로 저장된다.

## 저장 형식 (API가 예전 버전일 때)
- 원인: `/api/appearance`는 Sites API가 자기 배포본의 `wardrobe.js`로 검사한다. v65 목록에는 `dino-hood`가 없어 "지원하지 않는 장식이 포함되어 있어요."로 거부됐다.
- 해결: `dist/wardrobe.js`의 `wireAppearance`/`readAppearance`. 보낼 때 `dino-hood`를 장식 목록에서 빼고 털 길이를 `정수 + 0.37`로 보낸다(API는 50~100 범위의 실수를 그대로 저장·중계한다). 받을 때 소수부 표시를 읽어 후드를 되돌린다. 적용 지점: 저장·presence 전송(`dist/social.js`), 입장 시 복원(`dist/social.js`), 모든 캐릭터 렌더(`dist/companion.js`의 `customize`).
- 확인: v65 `validateAppearance`가 원래 형식은 같은 오류로 거부하고 전송 형식은 받아들임. v65 검증 규칙으로 돌린 로컬 서버에서 저장 → presence 동기화 6초 → 새로고침 후에도 `eyes-sparkle,dino-hood`, 털 길이 88로 복원됨. `tests/wardrobe-wire.test.mjs`.
- 미확인: 운영 서버에서의 실제 저장, 다른 접속자 화면에서의 표시(같은 렌더 경로를 쓰지만 브라우저 두 대로 확인하지 않음).
- Sites API를 새 목록으로 재배포해도 이 형식은 그대로 동작한다.
