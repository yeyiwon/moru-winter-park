## UI의 실제 원인과 수정

v35의 마지막 공통 테마 `ui-system.css`가 이전 유리 UI에 `rgba(25,58,65,.72)`와 `rgba(17,36,50,.76)`의 청록 그라데이션을 덮었다. 화면별 임의 색상을 공통화하는 과정에서 사용자가 원한 투명도를 잃었다. 과거 `glass.css`의 투과감·얇은 경계·테두리 없는 닫기 버튼을 복구하되, 30px 블러는 되돌리지 않는다.

- 표면: `rgba(9,18,37,.46)`. 장식용 청록·보라 그라데이션 제거.
- 경계: `rgba(218,234,255,.2)`, 선택: 같은 아이스 화이트의 12% 투명도.
- 블러: PC 10px, 모바일 5px. 저품질은 0px. 투명도 감소 접근성 설정은 불투명 네이비를 쓴다.
- 제목/닫기와 카테고리 탭을 별도 행으로 묶은 `studio-header`. 사용자 추가 요청에 따라 '설정'을 18px/600, 하위 탭을 12px/450으로 구분한다. 같은 행에 나란히 두지 않는다.
- 바깥 프레임은 탭마다 크기가 바뀌지 않는다. 내용만 스크롤하며 지도는 나머지 높이를 모두 사용한다. 불필요한 지도 하단 안내문은 숨겼다.
- 닫기는 44px 투명 터치 영역을 유지한다. 키보드 포커스는 가는 박스 대신 밝기 배경으로 표시한다.
- 실제 브라우저에서 발견한 공통 `header { position:fixed }` 충돌과 예전 `aurora.css`/`metaverse.css`의 커스터마이징 전용 창 크기 규칙을 제거했다. 제목과 내용 영역의 경계, 모든 탭의 동일한 프레임 크기를 자동으로 검사한다.
- 설정을 연 상태에서 화면 크기·그래픽 품질을 바꾸면 WebGL 버퍼가 지워지지만 일시 정지 로직이 재렌더를 생략했다. 변경 시 정지된 장면을 한 번만 다시 그려 유리 패널 뒤 월드를 보존한다. 계속 렌더하거나 게임 시뮬레이션을 재개하지 않는다.

- 놀이공원→료칸 다리는 약 22.77m. 진입·도착에 6m 직선 여유를 둔다.
- 스키장→료칸은 약 55.52m. 료칸을 앞쪽으로 이동하면서 이 다리는 길어졌다. 기존 스키장 안전 경계를 유지하고 별도 북쪽 입구로 연결한다. 이 길이를 줄이려고 설산을 늘리거나 임시 지형을 추가하지 않는다.
- 북쪽 진입을 막던 바위 군집 1개와 소나무 1개를 정원 가장자리로 이동했다. 건물 정면 길은 차양 기둥 사이의 축으로 맞췄다.
- 관람차는 기존 원형 휠과 2인 좌석을 유지하면서 정면 9.5m 위치에 탑승 트리거와 대기 공간을 맞췄다. 대기 바닥은 기존 구조물 배치에 합쳐 별도 메시를 늘리지 않는다.
- 산책로는 넓은 순환로와 정면 연결로로 정리했다. 부스 전면은 길을 바라보고 가로등은 통행로 밖에 정렬한다. 공중에서 임의 직선을 긋는 대신 실제 충돌을 통과한 경로를 부드러운 기존 눈길 재질로 생성한다.

## 구역 단위 좌표와 충돌

`region-layout.js`의 중심·회전·로컬 앵커가 다리, 도착점, 랜드마크의 기준이다. `spa-transform.js`는 원래 모델의 `(0,119)` 중심을 보존하며 `spaToWorld` / `spaToLocal`을 제공한다.

료칸 본관, 탕, 폭포, 정원, 발광 효과, 입장 클릭 메시, 보행로, 광원은 `spa-resort` 부모에 최종 Transform을 한 번 적용한다. 정적 메시를 먼저 로컬 좌표에서 병합한다. 물 메시나 캐릭터를 임의 변형하지 않는다.

별도로 계산되는 영역도 같은 변환을 적용한다.

- 지형 외곽·암반·수면 구멍·지도 투영과 탐색 범위
- 타원형 탕 판정·입퇴장 계단·회전한 벽/문 콜라이더
- 카메라 방향·실내 포털·순간이동 지점
- 서버의 위치 검증, 환경음 위치, 실내 발소리와 눈 발자국 제외 영역
- 수면의 캐릭터 파동·빛 반사·법선. 회전 뒤에도 빛이 실제 등 위치를 따라간다.

넓은 충돌 검색은 회전한 경계 상자를 사용하고, 정밀 판정은 로컬 좌표에서 수행한다. 경계 상자를 그대로 벽으로 사용해 입구가 막히지 않도록 했다. 발자국의 산책로 샘플도 부모 Transform을 반영한다.

## 팝콘과 비눗방울

기존 팝콘 부스에서 팝콘을 받으면 손에 든 채 이동한다. E로 먹는 동작을 실행하고 다른 아이템을 받으면 교체한다. 새 부스를 추가하지 않았다. 팝콘 버킷·알갱이는 병합된 2개 재질을 쓴다.

비눗방울은 E를 **누르고 있는 동안** 계속 불며 이동할 수 있다. 모바일은 이동 스틱과 별도의 비눗방울 버튼을 함께 누른다. 키/터치 해제, 취소, 창 이탈, 패널 열기, 아이템 교체 시 불기 상태를 정리한다. 들고 있기와 불기 상태를 분리해 서버에 동기화하며, 카메라를 얼굴 앞으로 강제로 돌리지 않는다. 입자는 기존 32개 풀 안에서 재사용한다.

## 지도 제작 과정

1. `region-layout.js`와 실제 모델·상호작용 앵커를 먼저 수정한다.
2. `node scripts/bake-paths.mjs`로 충돌을 피하는 산책로를 생성한다.
3. 로컬 서버에서 `PROFILE_URL=http://127.0.0.1:4185 MAP_OUTPUT=qa/browser-v36/map-render node scripts/render-world-map.mjs` 실행.
4. 실제 Three.js 월드를 정적으로 렌더해 `winter-world-map.webp`와 투영 정보 `map-atlas.js`를 함께 갱신한다.
5. 지도 아이콘은 실제 안전 도착 좌표를 투영한다. PC 호버/클릭, 모바일 선택 후 재터치와 기존 확대·이동 기능을 유지한다.

지도에 별도 실시간 Three.js 렌더러를 추가하지 않는다. 최종 지형/모델/길이 바뀌면 2~4를 다시 실행한다.

## 성능 측정

Apple M2 / 실제 Chrome, 동일한 `medium` 품질, 같은 장소 ID에서 각각 8초간 게임 렌더 콜백을 수집했다. 다른 자동 브라우저 검사와 동시에 실행하지 않았다. PC 1280×800, 모바일 에뮬레이션 390×844/DPR 3. 기준은 위 v35 커밋 전체 모듈 그래프이며 일부 옛 파일을 현재 코드와 혼합하지 않는다.

| desktop / plaza | 60.0 → 60.0 | 16.7 → 16.7 | 782 → 765 |
| desktop / spa-garden | 60.0 → 59.9 | 16.7 → 16.7 | 223 → 106 |
| mobile / plaza | 59.9 → 59.6 | 16.8 → 16.7 | 548 → 551 |

두 구역의 배치와 카메라 앵커가 달라져 보이는 오브젝트 수 역시 달라진다. draw calls 차이를 동일 장면 최적화 효과라고 해석하지 않는다. 짧은 표본에서 큰 프레임 저하는 관측되지 않았지만 실제 모바일 GPU·장시간 발열·대규모 동시 접속은 미검증이다. [원자료](../qa/browser-v36/performance/). GPU 타이머는 이번 비교에서 수집하지 않았다.

배포 파일 총 22,187,536 bytes, JS/CSS gzip 합계 932,783 bytes. 기존 24MiB / 1,250KiB 예산 이내다. 새 production dependency, 실시간 지도 렌더러, 추가 상시 PointLight는 도입하지 않았다.
