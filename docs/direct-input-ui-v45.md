# v45 · 직접 시야 조작과 UI 정리

작성일: 2026-11-19. 이 문서의 `v45`는 변경 묶음 이름이며 Sites 저장·배포 버전 번호와 다르다.

## 상태와 범위

현재 작업 소스에서 직접 카메라 입력, 활동 탭, 음악 제어 정리, 닉네임 인라인 편집을 반영했다. 아래에는 완료된 범위별·관련 통합 자동 검사와 320/390px 브라우저 UI 확인을 기록한다. 최종 전체 회귀 457개와 Worker·Vercel production build, 정적 용량 예산을 통과했다. 운영 배포 결과는 완료 후 아래에 추가한다. 이전 운영 배포 결과는 [v44 배포 기록](release-v44-2026-11-19.md)에 보존한다.

실물 Windows PC·휴대폰의 조작감, 실제 GPU 렌더링, FPS·프레임 시간·발열·배터리·오디오 연속 재생 성능은 **UNKNOWN**이다. DOM 이벤트 검사는 실물 기기에서의 성능 검증을 대신하지 않는다.

## 원인과 선택 이유

기존 카메라는 별도의 시야 조절 모드를 활성화해야 일부 드래그·핀치·휠 입력을 받았다. 같은 장면을 만져도 현재 모드와 입력 장치에 따라 반응이 달라지는 구조였다. 게임 화면의 직접 조작에 모드 전환이 끼어드는 조건을 없애고, 짧은 클릭·탭과 드래그를 구분하도록 변경했다. 기본 카메라 각도와 시설·실내의 기존 카메라 정책은 계속 사용한다.

별도 카메라 조절 패널·버튼과 그 전용 CSS/모듈을 제거했다. 지식집과 불꽃놀이는 시간·날씨 설정에서 독립된 `활동` 탭으로 옮겼다. 음악 제어는 전체 음소거와 배경음악 켜기/끄기를 유지하고, 반복 버튼 옆의 중복 음소거만 제거했다. 커마의 닉네임은 캐릭터 미리보기 위의 같은 행에서 편집하도록 바꿨다.

## 직접 입력 동작

| 입력 | 현재 동작 |
| --- | --- |
| PC 마우스 이동만 하기 | 카메라가 회전하지 않는다. |
| PC 왼쪽 또는 오른쪽 버튼을 누른 채 월드 드래그 | 카메라를 회전한다. 오른쪽 버튼은 이동 명령을 만들지 않는다. |
| 월드를 짧게 클릭·탭 | 기존 월드 상호작용을 수행한다. 바닥에서는 이동하며, 좌석·시설·트리 등은 기존 상호작용 판정을 유지한다. |
| PC 휠 | 확대·축소한다. 픽셀·줄·페이지 단위 입력을 환산하고 한 이벤트의 변화를 제한한다. Ctrl/Meta를 누른 브라우저 확대 단축 입력은 가로채지 않는다. |
| 모바일 월드 한 손가락 드래그 | 카메라를 회전한다. |
| 모바일 월드 두 손가락 핀치 | 확대·축소한다. 조이스틱·점프 등 다른 컨트롤이 소유한 손가락은 핀치에 섞이지 않는다. |
| PC `R` | 입력창·모달·중단 상태가 아닐 때 기본 시야로 돌아간다. |
| 메뉴 열기·중단·포커스 이탈·포인터 취소·캡처 상실 | 진행 중 입력과 포인터 캡처를 정리해 이후 호버나 터치가 이전 드래그를 이어 가지 않게 한다. |

구현의 짧은 탭 판정은 이동 거리 7 CSS px 이내, 500ms 이내다. 드래그 또는 핀치로 판정된 입력은 손을 뗄 때 이동으로 재해석하지 않는다. 이 값은 현재 구현값이며 모든 기기에 대한 최적값을 측정했다는 뜻은 아니다.

독립 리뷰에서 기존 학습 패널 `#learning`은 `lab:pause` 대신 `lab:open`을 보내는 경로가 확인됐다. 그 경로에서는 잡힌 포인터가 남을 수 있어 `lab:open`과 `lab:close`에도 입력 정리를 연결했다. 새 회귀 검사는 수정 전 캡처 수 `2`가 남아 실패했고 수정 후 `0`으로 통과했다.

## 활동과 음악 UI

- 설정 → **활동**에서 `내 지식집`과 불꽃놀이 신청을 연다. `#pane-activities #studio-public-actions`가 공용 활동 버튼의 목적지다.
- 지식집은 기존 버튼 ID로 열리므로 개인 기록·퀴즈 흐름을 변경하지 않는다. 익명 세션별 기록과 서버 저장 계약은 [지식집 문서](quiz-journal.md)를 따른다.
- 불꽃놀이 버튼은 새 활동 그룹이 존재할 때만 연결한다. 시간·날씨 탭이나 다른 위치의 같은 ID로 되돌아가는 fallback을 없앴다. 서버 신청·예고·공연·재신청 대기 계약은 유지한다.
- `전체반복` 옆 `음악 음소거` 버튼, 해당 이벤트 처리, 구독 중 DOM 참조를 제거했다. 전체 음소거, 배경음악 켜기/끄기, 음악 볼륨, 환경음·효과음, 셔플·반복은 유지한다.
- 음소거를 해제해도 사용자가 정한 음악 볼륨을 임의로 다른 값으로 바꾸지 않는다. 기존에 저장한 0 볼륨도 유효한 설정으로 남긴다.

## 닉네임 같은 행 편집

닉네임을 누르면 같은 행이 입력·저장·취소 컨트롤로 바뀐다. 닉네임 저장은 서버 응답을 기다리며, 확인 전에 화면의 확정 닉네임을 바꾸지 않는다. 저장 중에는 중복 제출과 초안 변경을 제한한다. 실패하면 초안과 오류를 그대로 보여 주어 같은 자리에서 다시 시도할 수 있다.

편집 도중 서버의 확정 닉네임이 새로 들어와도 작성 중인 초안을 덮어쓰지 않는다. 취소하면 최신 확정 닉네임으로 돌아간다. 한글 조합 중 Enter는 제출하지 않으며, 닉네임 편집 중 Esc는 우선 닉네임 편집을 닫는다. 커마를 떠난 뒤 저장 응답이 도착해도 다른 패널의 포커스를 가져오지 않는다. 10자 제한은 기존의 보이는 글자 단위 검증을 유지한다.

## 실제 검증 기록

범위별 검사는 서로 중복될 수 있으므로 개수를 더해서 전체 테스트 수로 표기하지 않는다.

### 음악·불꽃놀이

```sh
node --test tests/settings.test.mjs tests/audio-engine.test.mjs tests/fireworks.test.mjs
```

**23/23 PASS**, 실행 시간 1612.8648ms. 중복 음소거 DOM 없이 실제 음악 모듈을 초기화하고, 음악 볼륨 27% 유지·전체 음소거와 BGM 스위치의 독립 동작·셔플·반복을 확인했다. 불꽃놀이 버튼의 새 활동 탭 연결과 잘못된 목적지 거부, 기존 서버 신청·대기·실패 처리 검사를 포함한다. 두 변경 모듈의 `node --check`와 해당 파일의 `git diff --check`도 통과했다.

### 직접 카메라 입력

```sh
node --experimental-vm-modules --test tests/free-camera-input.test.mjs tests/metaverse-controls.test.mjs tests/mobile-v38.test.mjs
```

최종 **18/18 PASS**, 실행 시간 1134.468515ms. JSDOM 이벤트로 호버·좌우 드래그·짧은 탭 임계값·휠 단위 환산·핀치와 조이스틱/점프 포인터 분리·모달/중단/포커스 이탈/취소/캡처 상실을 검증했다. 앞선 17/17 결과에 위 학습 패널 캡처 정리 회귀 1개를 추가한 결과다. `git diff --check` 통과.

### 닉네임

```sh
node --experimental-vm-modules --test tests/nickname-inline.test.mjs tests/community-ui.test.mjs tests/social-ui.test.mjs
```

**18/18 PASS**. 서버 확인 대기·실패 초안·재시도·편집 중 확정 이름 갱신·취소·한글 조합·저장 완료 후 다른 패널 포커스 유지와 기존 게스트·소셜 UI 동작을 검증했다.

### 관련 통합 검사와 브라우저 UI

루트가 `community-ui`, `nickname-inline`, `free-camera-input`, `settings`, `fireworks` 5개 테스트 파일을 함께 실행해 **36/36 PASS**를 확인했다. 이 결과는 병렬 편집 도중 구버전 테스트 파일로 실행했던 중간 25/26 결과를 대체한다. 이후 학습 패널 캡처 정리 회귀 1개가 추가됐고, 위 직접 입력 검사에서 18/18 통과했다. 전체 테스트 개수를 합산하지 않는다.

실제 브라우저 UI에서 390px·320px 너비로 닉네임을 눌러 편집 전후를 확인했다. 프로필 영역 높이 68px, 캐릭터 미리보기 canvas 시작 위치 193px이 편집 전후 동일했고 가로 넘침은 없었다. 입력 글자 16px, 저장·취소 터치 영역 44px을 확인했다. 이 환경은 GPU를 사용할 수 없어 실제 3D 출력·카메라 이동 영상·렌더링 성능은 확인하지 못했다.

## 후속 검증 기록 위치

루트가 실제로 실행한 전체 검사, 양쪽 배포 빌드, 추가 브라우저 QA와 배포 결과를 이 문서에 추가한다. 실기 성능을 측정하게 되면 기종·브라우저·해상도·품질 설정·측정 상황을 함께 적는다. 현재 변경으로 렉이 사라졌다거나 모든 기기에서 동일한 FPS가 나온다고 단정하지 않는다.
