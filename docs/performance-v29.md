# v29 성능 최적화

## 원인과 변경

- 정적 오브젝트를 합칠 때 indexed geometry를 매번 풀어 써서 같은 꼭짓점 데이터가 반복됐다. `mesh-batch.js`는 기존 삼각형·노멀·UV·배치를 보존하면서 인덱스를 유지한다. 성·트리·나무·일루미네이션을 삭제하지 않았다.
- 카메라 충돌 검사가 거대한 합친 메시의 많은 삼각형을 반복 검사했다. `camera-raycast.js`는 64개 삼각형 단위의 bounding-volume hierarchy를 사용하며, 변환·앞뒷면·draw range·geometry 갱신을 보존한다.
- 공간 전체의 PointLight 24개를 매 프레임 셰이더에서 계산했다. 발광 장식·후광·눈 위 반사 표현은 유지하고 실제 주변 조명은 PC 6개, 터치 기기 4개의 고정 슬롯으로 처리한다. 숨겨진 실내 조명과 멀리 떨어진 광원은 제외한다.
- 작은 화면 크기로 보이는 캐릭터에도 털 26,000가닥을 그렸다. 화면에 보이는 크기에 맞춰 그리는 가닥 수만 줄이고 가까이 보면 모두 복원한다. 원래 실루엣과 털 인스턴스 위치, 커스터마이징 모델은 유지한다.
- 화면 밖 다른 플레이어의 포즈·리액션 계산과 이름표 처리를 중단한다. 서버 접속·위치 동기화는 계속 유지한다. 다시 보일 때 최신 상태로 표시한다.
- 설정의 시각 효과에 자동 모드를 추가했다. 지속적으로 느린 프레임에서만 렌더 해상도를 단계적으로 낮추며, 안정적인 여유가 지속되면 복원한다. 숨겨진 탭의 긴 중단은 측정에서 제외한다. 수동 설정은 자동 변경하지 않는다.
- 그림자 갱신은 초당 12~24회로 제한하고, HDR 렌더 타깃의 MSAA는 최대 4배에서 2배로 줄였다. 효과 강도에 따라 MSAA를 생략한다. 프레임마다 움직임을 계산하는 주기는 유지한다.
- 후처리 마지막 패스만 표시하던 그리기 통계를 고쳐 전체 월드 렌더 비용이 성능 측정에 포함되게 했다.

## 동일 장면 CPU 비교

`scripts/profile-world.mjs`로 v28 소스와 수정 소스를 각각 별도 프로세스에서 실행했다. 시각은 고정했고 같은 광장·성·스키장 카메라를 사용했다. 수치는 단일 비교 실행이며 브라우저 FPS가 아니다. 원시 결과는 `qa/performance-v29.json`에 저장했다.

| 항목 | 이전 | 이후 |
| --- | ---: | ---: |
| 모델 버퍼 (attributes + indices) | 394.3 MB | 222.2 MB |
| 지오메트리 꼭짓점 | 11,658,013 | 5,516,430 |
| 메시 오브젝트 수 (캐릭터 포함) | 642 | 642 |
| 광장 화면 삼각형 추정 | 3,636,792 | 2,980,662 |
| 광장 CPU 반복 계산 평균 | 5.14 ms | 0.53 ms |
| 성 CPU 반복 계산 평균 | 2.67 ms | 0.45 ms |
| 스키장 CPU 반복 계산 평균 | 4.07 ms | 1.00 ms |

CPU 반복 계산은 월드 애니메이션·캐릭터 포즈·카메라 충돌·행렬 갱신을 포함한다. HTML UI, 실제 WebGL draw, GPU 시간, 네트워크 지연은 포함하지 않는다. 전체 앱 메모리가 44% 감소했다는 의미가 아니다.

## 검증 범위와 남은 확인

- 기존 이동·스키·리프트·공동 탑승·온천·실내·캐릭터·트리·UI·서버 회귀 검사.
- 실제 삼각형과 가속 충돌 검사의 일치, 변환·양면·draw range·수정 후 캐시 갱신.
- 합친 메시의 모든 삼각형과 UV 보존, 인덱스 유지.
- 조명 슬롯 제한 및 숨겨진 실내 제외, 자동 설정의 지연과 수동 설정 유지.
- 화면 밖 플레이어의 상태 보존과 재등장, 가까이에서 원래 털 복원.
- 실제 PC·모바일 브라우저의 GPU FPS와 시각 품질은 브라우저 조작 환경이 없어 미검증이다. 설정 → 소리 → 화면 성능 확인에서 10초 측정으로 실제 기기 결과를 확인할 수 있다.
