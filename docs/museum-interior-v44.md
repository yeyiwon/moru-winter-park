# 별빛 만물관 실내 보강

## 변경 이유와 범위

천문대 실내의 기존 전시는 단순한 원통 받침과 작은 주제 오브젝트 위주였다. 전시 양옆의 기둥은 전시 중심에서 ±4.4m 떨어져 있어, 실제 충돌 반경 2.4m 바깥으로 장식이 뻗어 있었다. 전시를 찾아 걸으며 퀴즈를 푸는 공간에 맞게 재질과 세부 형태를 보강하고, 가구의 실물 범위도 기존 충돌 범위 안으로 정리했다.

실제 데이터에 있는 **과학·자연·역사·논리 4개 전시관과 중앙 오러리**를 유지한다. 외관, 입구와 출구, 각 전시 위치, 이동 경로, 천장 높이 28m, 퀴즈 데이터 및 개인 기록 API는 이 변경에서 수정하지 않는다. 카메라 정책과 퀴즈의 화면 중앙 배치는 별도 작업이다.

## 형태와 재질

- **전시 캐비닛:** 겨울 아이보리의 하단 몰딩, 짙은 청색 몸체, 브라스 세로 홈과 테두리, 앞이 열린 곡면 유리 뒤판으로 구성한다. 책과 펼친 페이지, 앞쪽 명패 레일이 전시 규모와 공예적 질감을 보강한다. 명패에 동작하지 않는 버튼을 만들지 않는다.
- **과학:** 반투명 구체와 프리즘, 브라스 궤도와 작은 위성으로 구성한 입체 천체 모형이다.
- **자연:** 간격이 일정한 이중나선과 두 개의 작은 식물 표본을 배치했다.
- **역사:** 성형한 도자기 몸체, 손잡이, 입구 테두리, 반복 문양, 작은 도편을 사용했다.
- **논리:** 기존의 실제로 회전하는 세 개 퍼즐 링을 유지하고 눈금과 빛나는 정렬점을 보강했다. 각 링은 중심에서 회전한다.
- **중앙 오러리:** 여러 단의 받침, 원주 눈금, 곡선 브라스 지지대, 6개 궤도와 행성으로 구성한다. 물체 전체의 수평 범위가 기존 중앙 fixture 안에 들어간다.
- **공간:** 기존 돔 안쪽의 큰 별자리 선과 별, 돔 하단 눈금, 바닥 나침반 및 전시 주변의 얇은 인레이를 추가한다. 천장 별자리 패턴은 공간을 위한 장식이며 실제 관측 데이터라고 표시하지 않는다.

주요 색은 겨울 아이보리·짙은 청색·따뜻한 브라스다. 전시별 색은 낮은 채도의 보조색으로 사용한다. 투명 재질은 일반 alpha 합성이며 실시간 굴절·투과 렌더 패스를 추가하지 않았다.

## 동선과 실제 기능

`interior-layout.js`의 기존 `museumFixtures`와 `interiorInteractions`를 계속 사용한다. 전시의 모든 mesh 정점을 실제 변환 행렬로 검사했을 때, 각 전시의 최대 수평 반경은 약 2.29m로 기존 2.4m fixture 안에 들어간다. 중앙 받침과 천체 모형도 기존 4.2m fixture 안에 들어간다. 바닥 인레이는 바닥에 붙인 장식이며 새 가구나 충돌체가 아니다.

`winter-experience.js`의 실제 근접 상호작용은 그대로 이어진다.

1. 각 전시 접근점에서 `전시 보기`를 누르면 해당 주제의 실제 전시 패널을 연다.
2. `퀴즈`를 누르면 같은 주제의 `openQuickQuiz({gallery})`를 호출한다.
3. 논리 전시의 기존 별자리 맞추기는 실제 세 링의 회전과 연결되어 있다.
4. 퀴즈의 `내 지식집`은 기존 익명 세션의 개인 기록을 연다.

새 장식은 이 기능을 대신하지 않는다. 새로운 문제를 생성하거나 출처를 만들어 넣지 않았다.

## 비용과 수명 관리

불투명 정적 부품은 기존 `mergeFinish()`로 재질별 병합한다. 책·명패·줄눈·눈금에는 builder의 공유 기본 geometry를 재사용한다. 투명 곡면은 전시마다 한 개이며 화면 전체를 덮는 유리 레이어를 추가하지 않는다. 실시간 광원은 기존 HemisphereLight 1개와 PointLight 1개를 유지한다.

| 생성된 장면의 구성 | 변경 전 | 변경 후 |
| --- | ---: | ---: |
| geometry가 있는 renderable 객체 | 63 | 88 |
| mesh 객체 | 61 | 84 |
| mesh 삼각형 | 143,355 | 142,735 |
| 투명 renderable 객체 | 5 | 13 |
| 실제 광원 | 2 | 2 |

위 값은 Three.js로 장면을 생성해 센 **구성 수치**다. `renderer.info.render.calls`, GPU 시간 또는 모바일 FPS 측정값이 아니다. 디테일을 추가하면서 기존 바닥의 다수 작은 구체와 겹친 외곽 기둥을 정리해 전체 삼각형 수는 소폭 줄었지만 renderable 수와 투명 객체 수는 늘었다. 이 차이의 실제 기기 비용은 아직 UNKNOWN이다.

- 낮은 품질에서는 배경 별의 draw range를 320개에서 100개로 줄이고, 기존 atmosphere의 입자 밀도 및 두 번째 리본 제한을 그대로 적용한다. 전시와 접근점은 숨기지 않는다.
- 낮은 품질의 천체·표본 모션 갱신은 최대 20Hz로 제한한다. 기본 모션 속도는 천천히 유지한다.
- reduced motion 상태에서는 현재 궤도와 표본의 회전 위치를 그대로 유지한다. 원점으로 다시 돌아가는 스냅이 없다.
- 숨겨진 부모나 실내는 갱신하지 않는다. 재입장 시 긴 전역 시간 차이가 모션에 한꺼번에 반영되지 않도록 증분을 제한한다.
- 실내 해제는 기존 `buildInteriors.release()`가 소유한 geometry/material을 정리한다. 해제된 실내의 늦은 update/react/puzzle 호출은 동작하지 않는다.

## 변경 파일

- `dist/museum-world.js`: 기존 실내에 세부 모델 연결, 제한된 모션과 품질/해제 처리. 외관 함수는 유지.
- `dist/museum-interior-details.js`: 캐비닛, 전시 모형, 책, 바닥 인레이, 돔 차트, 중앙 오러리.
- `tests/museum-interior.test.mjs`: 실제 모델 범위, 비용 한도, reduced motion, 가시성, 해제, 전시→퀴즈→개인지식집 연결.
- `dist/sw.js`: 신규 모듈의 오프라인 자산 목록 등록은 통합 단계에서 반영.
- `scripts/export-museum-review.mjs`, `scripts/render-museum-review.py`: 생성 geometry의 CPU 참고 렌더를 재현하는 도구.

## 실제 검증

```sh
node --experimental-vm-modules --test tests/museum-interior.test.mjs tests/districts-v32.test.mjs tests/retreat-atmosphere.test.mjs tests/interiors.test.mjs
```

19개 검사가 통과했다. 새로 추가한 5개는 모든 전시 정점이 기존 충돌 범위 안에 있는지, 실제 경로가 연결되는지, 유한한 geometry와 비용 상한, 광원/투과 패스 미증가, reduced motion과 숨김 처리, 두 번의 생성·해제에서 각 자원이 한 번만 정리되는지, 실제 `winter-experience` 근접 UI가 각 전시와 퀴즈를 여는지 확인한다. 개인 지식집도 실제 모듈로 열고 응답 처리가 끝나는 것까지 확인한다.

CPU 형태 참고 렌더:

```sh
node scripts/export-museum-review.mjs /tmp/museum-v44-review
blender -b -t 4 --python scripts/render-museum-review.py -- /tmp/museum-v44-review
```

최종 참고 PNG와 작은 수치 파일만 `qa/museum-v44/`에 둔다. 큰 재생성용 geometry JSON은 위 임시 디렉터리에 남긴다. Blender 4.3.2 CPU 렌더로 캐비닛·중앙 기구·바닥 고리 사이에 열린 보행 공간이 있는지, 실내 물체의 형태와 겹침을 확인했다. 이 환경에는 OpenImageDenoise가 없어 denoise를 끄고 24 samples로 렌더했다.

**이 PNG는 브라우저 완성 화면이 아니다.** 절차적 WebGL shader, 후처리, 실제 조명 예산, 사용자 카메라와 동작을 재현하지 않는다. 검사 조명을 사용하고 Points와 Lines는 형태 확인용으로 변환했다. 실제 모바일 GPU의 유리 합성 순서, 프레임 시간, 발열, 게임 안에서의 최종 시각 품질은 기기 검증이 필요하며 현재 UNKNOWN이다.
