# v37 — Luminous 로딩, 3D 불꽃놀이, 휴대 스파클러

## 로딩

제공된 레퍼런스의 얇은 샴페인 골드 나선 트리를 SVG 한 경로로 그린다. `luminous-loading.js`는 중심선·얇은 발광·주변 광채를 분리한다. 실제 경로 길이를 따라 이동하는 끝점과 경로 주변의 소수 입자만 사용한다. 최신 요청대로 아래의 넓은 곡선에서 꼭대기로 올라가며 2.7초 동안 그려지고 필요한 동안만 4.15초 루프를 반복한다.

최신 사용자 정정에 따라 텍스트는 **`Loading ...`**이며, 양옆 선·별 장식은 제거했다. 새 배경 풍경이나 문구는 없다. 준비된 월드 위에는 PC 24px / 작은 화면 18px backdrop blur를 적용한다. 최초 장면이 없을 때만 짙은 네이비 대체 배경을 사용한다.

`loading-state.js`의 실제 에셋·월드·캐릭터/실내·첫 프레임·서버 준비와 연동한다. 완료하면 진행 중인 루프를 기다리지 않고 짧게 사라진다. 료칸과 천문대 전환도 실제 입장 요청/준비에 맞춰 표시한다. 오류는 재시도가 가능하고 가짜 퍼센트는 표시하지 않는다. Reduced Motion에서는 그리기 반복을 멈춘다.

## 불꽃놀이 구조

`firework-score.js`가 시드 기반 74초·26발 공연을 만든다. Opening → 색상 전개 → 대형 구형 불꽃 → Golden Willow → Glitter Finale 순서다. 5개 패턴(Chrysanthemum, Peony, Golden Willow, Ring, Glitter)을 서로 다른 높이·깊이·시각에 배치한다.

`winter-fireworks.js`의 단일 Points/BufferGeometry/ShaderMaterial에서 발사·상승·폭발·중력 낙하·바람·감쇠와 꼬리를 GPU로 계산한다. 각 파티클마다 매 프레임 JS 객체를 만들거나 네트워크로 위치를 보내지 않는다. 26발 × 240개 × 12개 꼬리 표본의 고정 버퍼(74,880개 정점)를 재사용하며 품질별 144/72개, 효과 감소 48개로 줄인다. 공연이 없으면 drawRange=0으로 그리지 않는다.

놀이공원 뒤의 안전한 발사 앵커는 변경된 스키 지형보다 높게 확보했다. 시설·다리·섬을 옮기지 않는다. additive 발광과 짧은 폭발 중심, 잔광을 구분하며 전체 화면 플래시나 강제 카메라 이동은 없다. 효과 감소에서는 중심 번쩍임을 줄인다.

## 서버·권한·음향

`server/fireworks.js`는 관리자 권한을 확인하고 공연 ID, startsAt, seed, state만 저장/전달한다. 일반 게스트의 시작 요청은 403이다. 수동 실행은 기존 관리자 패널에 통합했다. 3초 준비·12초 재실행 제한을 두고 자동 공연은 기본 비활성화한다. 중간 접속자는 서버 시작 시각을 기준으로 현재 공연 지점부터 본다.

`audio-engine.js`의 기존 효과음 볼륨·음소거 정책을 따른다. 발사와 폭발은 서로 다른 시각에 재생되고 거리로 음량과 지연을 계산한다. 사용자의 오디오 제스처 허용 전 자동 재생하지 않는다.

배포 경로 점검에서 `server/vercel-proxy.js`가 region/operations/world-state/experience/fireworks를 허용 목록에서 누락한 것을 발견해 연결했다. 인증 헤더는 외부 클라이언트가 주입할 수 없고 권한 검증은 기존 서버에서 유지한다. Vercel 방문자에게 Sites 관리자 인증이 자동 부여되는 것은 아니다.

## 휴대 스파클러

기존 빈 키오스크를 이용하며 새 섬·시설 동선을 만들지 않는다. 스파클러를 챙기면 손에 들고 걸어 다닐 수 있고, 다른 물건을 들면 기존 효과를 정리한다. `hand-sparkler.js`는 고정 파티클 버퍼로 작은 불티를 표현하고 기존 활동 상태를 통해 다른 방문자에게도 휴대 상태를 표시한다.
