# v47 — UI 간격, 채팅과 편안한 시점

2026-11-19. v46 실행 소스 위에서 수정했다. 구역 좌표, 시설 배치, 서버 권한, 공유 데이터와 Cloudflare 실시간 프로토콜은 변경하지 않는다.

## 확인한 원인과 변경

- 관리 화면의 연속된 행을 개별 섹션과 2열 운영 지표로 구분했다. 새로고침은 상단, 로그아웃은 마지막에 두고 기존 글래스 색상을 유지했다. 설정 탭은 중앙 정렬, 초대 URL/복사는 하나의 외곽선 안에서 같은 높이로 배치한다.
- 닉네임 입력과 글자 수 사이 간격을 확보하고 확인/X 대신 `저장·취소`를 표시한다. 채팅은 전송 아이콘과 `닫기`를 같은 44px 영역 안에서 정렬한다.
- 추가 피드백에 따라 저장·전송의 개별 배경과 테두리를 제거했다. 입력창 내부에서는 텍스트/아이콘과 여백만 사용하고, hover는 글자 밝기, press는 투명도로 반응한다. 키보드 초점은 텍스트 밑줄/아이콘 강조로 남긴다. [Apple의 버튼 가이드](https://developer.apple.com/design/human-interface-guidelines/buttons)의 간결한 버튼 구분과 일관된 조작 크기를 참고했으며 특정 스타일의 인기 순위를 주장하지 않는다.
- **채팅의 최신 요구:** 자신의 머리 위 말풍선은 유지한다. 탐험 중 왼쪽 대화 기록은 숨기며, 입력을 열 때만 기존 10분/50건 범위의 대화를 표시한다. 큰 패널 배경·테두리와 메시지 신고 버튼을 제거했다. 개인 숨김과 서버 관리 권한은 유지한다. 기록 전체를 다시 그릴 때 입장 애니메이션을 반복하지 않고, 과거 대화를 읽는 스크롤 위치를 보존한다.
- 트리 상태 문구가 하단 도크에 추가 행을 만들던 문제를 해결했다. 안내는 상단에 표시하고, 상단 알림만 조금 어두운 반투명 유리 색으로 구분한다. `앉기`의 별도 버튼 규칙을 제거하고 모든 근접 행동 버튼은 10px 모서리/44px 이상 터치 영역을 공유한다. 표시 이름은 `트리`로 줄였다.
- 트리를 열 때 강제로 반대 방향을 바라보는 회전과 초점/거리의 서로 다른 보간이 불안정한 시점을 만들었다. 현재 방향을 유지하고 초점·회전·거리를 같은 2초 곡선으로 움직인다. 트리 잎과 카메라가 겹치면 해당 잎을 흐리게 하되 벽의 충돌은 유지한다.
- 최신 요청에 따라 장식이 도착해도 꾸미기 시점과 도크를 유지한다. 직접 닫을 때만 일반 탐험 시점으로 복귀한다. 초기 구도 전환 도중 등록했을 때도 충돌 보정이 반영된 실제 카메라 거리에서 멈춰 연속 배치를 방해하지 않는다. 목표 거리만 고정하면 남아 있던 충돌 복구가 카메라를 더 멀리 움직일 수 있었다. 다른 사용자의 장식은 카메라를 움직이지 않는다. 수동 시점 조작은 자동 전환을 중단한다.
- 회전목마는 기본 거리 24, 낮은 시야 각도로 전체 말과 주변을 볼 수 있게 했다. 탑승 중 가리는 회전목마 메시만 부드럽게 투명하게 하여 기둥 때문에 시야가 갑자기 짧아지지 않게 했다. 주변 건물 충돌, 자유 회전, 하차 후 원래 거리 복귀는 유지한다.
- 장식 선택·소원 작성·소원 목록은 실제 장식 Geometry와 금속 프레임을 기존 렌더러로 그린 96px 미리보기를 사용한다. 새 WebGL 컨텍스트는 만들지 않는다. 색상 변경 중 기존 3D 이미지를 유지하고, 이미 지난 색상의 GPU 작업을 건너뛴다. 드래그 중 선택 항목만 갱신하고 확정 시 전체 선택지를 갱신한다.
- 장식 비행에는 기존 풀 안에서 두 겹의 일렁이는 금빛 궤적과 별가루를 적용한다. 입자 상한은 960/480/160으로 동일하고, 임시 궤적 버퍼만 늘린다. 도착 시 반짝임과 기존 차임을 유지하고 임시 효과를 회수한다.
- 불꽃놀이 알림은 진행 상태만 표시하며 별도 보기 버튼이나 강제 카메라 전환을 제거했다.

## 검증과 한계

저장·전송 버튼의 기본/hover 상태와 44px 터치 영역을 추가로 **8/8** 확인했다([최신 버튼 화면 및 결과](../qa/comfort-v47/inline-actions/report.json)).

브라우저 기능 검사 **50/50**, [추가 모바일 회귀 검사](../qa/comfort-v47/regression/ui.json) **15/15** PASS. 예외 0건. [검증 파일](../qa/comfort-v47/after/report.json)에 원시 결과를 기록했다. PC 1280×800, 모바일 터치 화면 390×844, 작은 화면 320×740을 실제 Mac Chrome에서 확인했다. 이는 실물 iPhone/Android/Windows 시험이 아니다.

JavaScript 소스 269개 검사, 자동 검사 494개, Vercel production build와 자산 예산 검사 PASS. TypeScript/lint 별도 명령은 이 저장소에 없다. 초기 전체 검사에서는 새 썸네일 경로에 필요한 `getClearAlpha` 등 GPU 모형 메서드가 테스트 fixture에 없어 실패했다. 실제 브라우저는 해당 API를 지원하며 fixture를 실제 경로에 맞춘 후 전체 재검사했다. 별도 검사로 빠른 100회 색상 입력이 GPU에 마지막 1회만 전달되는지, 캐시 재사용과 이미지 유지, 실제 회전목마의 한 바퀴 전체 카메라 가시성을 확인했다.

카메라 기록의 초기 requestAnimationFrame 타임스탬프가 측정 시작보다 앞설 수 있으므로 양의 60ms 미만 간격만 60Hz 이동량으로 정규화한다. 이 값은 카메라 연속성 검사이며 FPS 개선 수치가 아니다. 스크린샷 저장이 비행 종료 시점을 넘길 수 있어 VFX와 시점 고정 여부는 비행 중 각 프레임에서 별도로 기록한다.

80회 연속 색상 입력 뒤 최종 3D 이미지가 표시될 때까지 PC 599ms, 모바일 화면 496ms를 관찰했다(최대 100ms 간격 polling 포함). 동일 조건의 이전 수치가 없어 속도 개선율은 주장하지 않는다. 별도 자동 검사에서는 100회 중간 요청이 GPU 렌더 1회로 합쳐지는 것을 확인했다.

추가 수정: 닉네임 저장 성공 문구를 비우고 오류 안내는 유지한다. 모바일 지도에만 남아 있던 `padding:10px 8px`, `gap:4px`, 탭 `padding:2px`를 제거해 모든 설정 탭과 동일한 12px 외곽 여백·44px 탭 높이로 맞췄다. 저장/실패 및 6개 탭 비교 7/7, 닉네임 관련 자동 검사 9/9, 카메라 자동 검사 23/23 PASS. 실제 장식 연속 등록 PC·모바일 15/15, 구도 전환 중 빠른 등록 7/7 PASS. [연속 꾸미기](../qa/comfort-v47/continuous-tree/report.json) · [빠른 등록](../qa/comfort-v47/early-tree/report.json). 기존 서버의 장식 저장 정책은 변경하지 않았으며 연속 꾸미기 중 자동 종료·카메라 복귀를 제거한 변경이다.

최신 추가 수정의 CI에서 기존 닉네임 통합 검사 2개가 이전 `저장됨` 문구를 기대하여 실패했다. 실제 저장 성공/실패·초점·재접속 검증은 유지하고, 성공 문구가 비어 있어야 한다는 최신 요구로 두 기대값을 변경했다. 전체 재검사 결과는 후속 배포 기록에 남긴다.

모바일 실물 기기 성능, GPU 메모리, 장시간 운영 부하는 **UNKNOWN**. 새 dependency, 서버 migration, 유료 서비스 추가 없음.
