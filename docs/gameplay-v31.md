# 게임플레이·UI·오디오 개선 v31

범위: 사용자가 확인한 **첨부 문서 + 스키 종료 처리 + 커스터마이징/소원 UI + BGM 3곡**. 기존 월드와 v30의 성능 구조를 유지했다.

## 확인한 원인과 변경

- **행동 종료**: 이전에는 버튼 DOM, 근접 안내, 장비, 오디오가 서로 다른 경로에서 정리됐다. `interaction-lifecycle.js`와 `winter-experience.js`에서 종료 처리를 모으고, 같은 장소의 안내는 실제로 구역을 벗어났다가 돌아왔을 때만 다시 표시한다. 스키 완주 때 속도·조향·기울기·터치 입력·효과음을 초기화하고 자동 대여 장비를 반환한다. 자동 재탑승/복귀 안내는 표시하지 않는다.
- **리프트**: 좌표계가 이중 변환되는 오류는 발견되지 않았다. 얼굴 높이의 안전바를 낮춰 앞쪽으로 옮겼고, 카메라는 두 좌석 가운데를 바라보며 탑승장 서쪽 구조물을 피하는 방향으로 바꿨다. 대기 구역의 안내 반경을 넓혔다. 기존 2인 좌석·서버 예약·개별 하차를 유지한다.
- **회전목마 카메라**: 실제 브라우저의 측면 충돌 광선이 `carousel-offset-lift-0-gold`를 약 0.92m 거리에서 감지해 카메라가 0.8m까지 당겨졌다. 승강 지지대도 기존 기둥처럼 실제 가림이 발생할 때만 재질 복사본으로 흐리게 처리한다. 원본 공유 재질은 변경하지 않으며 하차 시 복원한다. 카메라 충돌의 시작점은 말 몸통 안의 구도 중심 대신 탑승 캐릭터에 둔다.
- **모닥불**: 이전에는 정상 리프트 모드에서만 불을 바라보는 방향이 적용됐다. 일반 보행으로 도착한 경우에도 몸 녹이기/굽기 동작 중 불 쪽으로 부드럽게 회전하고 이동 시 해제한다.
- **스키장 지형**: 정상 외곽의 높이 변화를 넓게 완화하되 상부 능선이 아래 정상의 휴식 평면을 덮지 않게 보호했다. 기존 코스와 정상 리프트 동선·트럭 받침·슬로프 폭을 유지한다. '상부 리프트' 표기는 '정상 리프트'로 정리했다.
- **트리거 판**: 투명도 0만 사용하는 감지용 메시를 렌더링에서 제외했다. 클릭 raycast와 근접 판정은 유지한다.
- **색상/장식 UI**: 기존 Flex 규칙에 Grid 속성만 붙어 있었고, 공통 label/input 스타일이 색상 선택 카드의 크기와 간격을 덮어썼다. 동일한 Grid 셀, 44px 터치 영역, 셀 안쪽 선택선, 아이콘/라벨의 독립 행으로 통일했다. 소원 공개 범위의 절대 위치 radio가 5px 넘치던 문제도 수정했다. 패널 내부 스크롤과 visualViewport 높이/오프셋을 반영한다.
- **소원**: 서버 등록이 확인되면 입력창을 닫고 캐릭터 앞에서 실제 장식 지오메트리를 띄운다. 기존 곡선·리본·도착 입자에 등록/상승/도착음을 연결하고 짧은 카메라 구도를 추가했다. 이동 또는 수동 카메라 조작으로 구도를 중단할 수 있다. 최종 위치·색상·origin은 서버 상태를 사용하며 중복 비행을 막는다. 소원 내용은 기본 비공개이며 직접 공개를 선택한 내용만 다른 방문자에게 보인다.
- **트리/커스터마이징**: 900개 전구의 매 프레임 CPU 색상 쓰기를 인스턴스 위상 셰이더로 옮겼다. 기존 풍성한 가지·전구·크리스털 장식·리본은 유지한다. 실버 안경은 렌즈와 프레임에 같은 곡률을 적용하고 입체 테두리/힌지/브리지를 보완했다. 별핀은 금속과 결정 장식으로, 별 눈은 광택 재질로 개선했다. 기존 하트 눈의 대칭/크기/곡면 앵커는 검증해 유지했다.
- **지도**: 클릭형 지도, 위치 표시, 확대/축소를 유지한다. 구역별 색상과 현재 위치/선택 상태, 글래스 스타일을 맞췄다. 세부 목적지 드롭다운은 추가하지 않았다.
- **료칸**: 기존 다다미·차·족욕·설경 창문·수면/수증기는 유지하며 미닫이문 동작과 소리를 보완했다. 통로와 겹치지 않는 식사 카운터·좌석·자기 접시·연어/쌀알/젓가락 모델 및 식사 동작을 추가했다. 식사 모델은 공유하고 캐릭터에서는 처음 식사할 때만 생성한다. 기존 유카타, 이동 취소, 실내 지연 로딩/퇴장 후 해제 정책을 유지한다.

## 실제 브라우저 검증

자동 검증은 별도 테스트 의존성으로 로컬 서버에만 연결한다. 테스트용 캐릭터 이동/관찰 기능은 브라우저 응답에서만 주입하며 배포 소스에는 노출하지 않는다.

- `scripts/verify-gameplay-v31.mjs` → `qa/browser-v31/verification.json` 및 원본 `gameplay-full.log`; 최종 시설 재검사 `verification-facilities.json`
- `scripts/verify-audio-v31.mjs` → `qa/browser-v31/audio-playback.json`
- 화면 비교: `qa/browser-v31/after-*-custom.png`, `after-*-wish.png`, 각 시설 카메라 캡처.
- 1440×900, 1024×700, 768×1024, 390×844, 320×640, 844×390에서 선택 카드 겹침, 팔레트 위치 변화, 가로 넘침, 미리보기 분리 확인.
- 두 브라우저의 소원 색상 저장·1회 비행, 같은 리프트의 별도 좌석과 개별 하차 확인.
- 실제 키보드 조향으로 스키 활강 완료 후 장비/카메라/UI 초기화 확인.
- 회전목마·관람차의 캐릭터 프레이밍 및 하차, 모닥불 이용/이동 종료, 료칸 차/족욕/식사/휴식 이용과 이동 종료 확인.
- 모바일 터치 에뮬레이션에서 이동과 점프 동시 입력 확인.

## 음악과 이용 조건

기존 8곡은 유지하고 아래 3곡을 추가한다. 이름만 등록한 것이 아니라 공식 페이지가 제공하는 원본 MP3를 확보해 AAC 96kbps로 변환했다. 전체 디코딩 검사와 실제 브라우저 재생을 수행했다.

| 곡 | 제작자 | 길이 | 추가 파일 |
| --- | --- | --- | --- |
| [Snow Globe](https://pixabay.com/music/christmas-snow-globe-432443/) | ondrosik | 108.65초 | `dist/audio/snow-globe.m4a` |
| [Wonderful Night](https://pixabay.com/music/christmas-wonderful-night-178596/) | moodmode | 139.25초 | `dist/audio/wonderful-night.m4a` |
| [Ethereal Winter Ballet Instrumental 02](https://pixabay.com/music/orchestral-ethereal-winter-ballet-instrumental-02-475693/) | alanajordan | 152.09초 | `dist/audio/ethereal-winter-ballet-02.m4a` |

각 공식 페이지의 Pixabay Content License 표기와 [라이선스 요약](https://pixabay.com/service/license-summary/), [이용 약관](https://pixabay.com/service/terms/)을 확인했다. 게임 안에 결합한 BGM으로 사용하며 원본 음원 재배포/다운로드 상품을 만들지 않는다. Wonderful Night에는 Content ID 등록 표시가 있어 게임 영상 게시 시 별도 권리 확인이 발생할 수 있다. Ethereal Winter Ballet 페이지에는 AI 생성 표시가 있다. 출처·제작자·해시·변환 정보는 `dist/audio/LICENSE.txt`, `qa/browser-v31/audio-provenance.json`에 기록했다.

PC/모바일 Chrome에서 세 곡 모두 `readyState=4`, 실제 재생 시간 증가, 유효한 duration, 재생 오류 없음 확인. 기존 2개 audio element와 `preload=none`을 유지해 사용자 입력 전 음원 요청은 0건이었다. 2.5초 전환 중에는 두 곡이 함께 재생되고 전환 후 이전 곡은 정지한다. 이전/다음/목록 반복/셔플/음소거와 BGM·환경음·효과음 볼륨 분리도 확인했다. 추가 효과음은 Web Audio 합성으로 직접 생성한다.

## 검증의 한계

- 모바일은 Chrome 터치/화면 크기 에뮬레이션이다. 실제 iPhone/Android 하드웨어와 OS 키보드를 직접 테스트한 것은 아니다.
- 첨부 문서가 언급한 오류 스크린샷 파일은 이 작업에 별도로 제공되지 않았다. 실제 로컬 월드를 캡처해 수정 전후를 확인했다.
- 성능 수치는 테스트한 Mac GPU/브라우저의 결과이며 모든 기기에서 특정 FPS를 보장하지 않는다. 기존 해상도 자동 조절·인스턴싱·영역별 컬링·실내 지연 로딩·원거리 접속자 갱신 제한을 유지한다.

## 최종 검사 결과

- 전체 자동 검사 287개 통과. 이후 모닥불 방향 수정에 대해 회전목마/상호작용 관련 17개를 다시 실행해 통과했다(신규 모닥불 사례 포함).
- Worker 빌드, Vercel 빌드, 변경 파일 공백 검사, 용량 제한 검사 통과.
- 배포 에셋 140개, 총 21,811,614 bytes(20.80 MiB), 압축 코드 881,306 bytes. 제한 24 MiB / 압축 코드 1,280,000 bytes 이내.
- PC/모바일 오디오, 6개 화면 크기 UI, 2인 리프트/소원 동기화, 실제 활강, 시설 이용 종료 검사 통과. 결과는 `qa/browser-v31/checks.json`과 각 검증 JSON/캡처에 저장했다.

### 성능 측정

Apple M2 / Chrome / ANGLE Metal, 자동 품질. PC 1280×800 DPR 1, 모바일 에뮬레이션 390×844 DPR 3. 각 장소 진입 후 안정화하고 5초간 실제 게임 프레임을 측정했다.

| 구역 | PC FPS | 모바일 에뮬레이션 FPS |
| --- | ---: | ---: |
| 광장 | 56.2 | 48.1 |
| 트리 | 60.0 | 59.8 |
| 관람차 | 42.2 | 60.0 |
| 회전목마 | 59.8 | 59.6 |
| 리프트 | 55.4 | 60.0 |
| 료칸 | 60.0 | 60.0 |

두 실행 모두 JavaScript 오류 및 측정 실패가 없었다. PC 관람차는 약 42FPS로 다른 구역보다 무겁다. 관람차 높이·시야·자동 품질은 실시간으로 달라지므로 기존 v30 기록과 엄밀한 동일 조건 A/B 비교로 해석하지 않는다. 실제 휴대폰의 GPU, 발열, Safari 오디오/키보드는 미검증이다.
