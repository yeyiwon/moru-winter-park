# v44 — 사용자가 정한 시야를 유지하는 카메라

## 원인과 변경 목적

기존 `park.js`에는 도착 전망, 이동 시작, 시설 탑승과 하차, 음식 제스처, 온천, 실내 입출구, 트리 장식, 모바일 resize가 각각 카메라 yaw·pitch·거리·FOV를 변경하는 경로가 있었다. 트리 장식은 PC 68m / 모바일 56m까지 거리를 늘리고 pitch를 0.17로 바꾸었다. 보행 카메라의 기준점과 충돌 검사 기준점에 점프 높이가 들어가 점프할 때 화면도 상하 이동했다. 실내 벽·천장을 피할 때 카메라 좌표의 성분별 clamp가 시야 각도를 다시 바꿀 수 있었다.

이번 변경은 카메라 설정의 소유권을 `camera-policy.js` 한 곳으로 모은다. **사용자가 요청한 시야**와 **벽이나 지형 때문에 실제 배치 가능한 거리**를 분리한다. 충돌이 사라져도 요청한 시야를 잃지 않고, 시설 이용 때문에 저장한 값을 덮어쓰지 않는다.

## 기본 시야와 입력

| 항목 | 값 / 동작 |
| --- | --- |
| 기본 yaw | 0.33 rad |
| 기본 pitch | 0.48 rad, 약 27.5도 |
| 기본 거리 | 월드 단위 16.5 |
| 세로 FOV | PC·모바일·시설·resize 모두 50도 |
| 초점 높이 | 캐릭터 지면 기준 origin + 0.45, 점프 높이 제외 |
| 수동 pitch 범위 | 0.08–1.08 rad |
| 수동 거리 범위 | 실외 8–48, 실내 5.5–24 |
| 첫 실내 시야 | yaw 0.5 rad / pitch 0.65 rad(약 37.2도) / 거리 15 |
| 롤 | 월드 up=(0,1,0)을 유지 |

평소 탭 이동과 WASD는 유지한다. 화면을 스치거나 두 손가락으로 만지는 행동은 기본 상태에서 카메라 변경으로 해석하지 않는다. `시야 조절` 모드에서 드래그·핀치·휠을 사용한다. PC 오른쪽 버튼 드래그는 명시적인 일회성 조절 의도로 허용한다. `완료`, blur, 패널 열기는 조절 모드만 종료하며 사용자가 정한 값을 지우지 않는다.

`기본` / `R`은 `lab:camera-reset`을 한 번 발행한다. `park.js`는 이 이벤트를 처리하고 기본 시야를 복구한다. `window.labCameraReady`와 `lab:camera-ready`로 실제 3D 초기화 성공 후에만 조절 UI를 노출한다. `getWinterCameraState()`는 요청값, 렌더 보간값, focus를 분리해 진단할 수 있다.

## 이동·시설·실내

- 보행·점프·작은 지형 변화는 pitch, yaw, 거리, FOV를 다시 설정하지 않는다. 높이 추적에는 작은 dead zone과 이동 속도 제한을 둔다. 지형 변화에 필요한 실제 이동은 계속 추적한다.
- 음식 제스처, 앉기, 회전목마, 관람차, 리프트, 온천은 요청 시야를 보존한다. 회전목마 말의 상하 bob은 focus 높이 2.85로 상쇄한다. 리프트·관람차의 실제 상승 높이와 공유 좌석의 중심점은 따라간다.
- 지도 이동은 목적지에서 동일한 요청 각도·거리로 카메라를 배치한다. 먼 공간 사이를 카메라가 날아가는 연출을 만들지 않는다.
- 실내 입장은 기존 화면 전환 안에서 카메라 위치를 바꾼다. 외부 시야를 저장하고 실내는 별도 값으로 관리한다. 실내에서 바꾼 값은 해당 방에 기억하고, 외부로 나오거나 지도 이동 시 외부 시야를 복구한다. 복구한 snapshot은 소비하므로 다음 이동에 오래된 값이 다시 적용되지 않는다.
- 실내 시야가 낮고 좁다는 후속 요청에 따라 첫 방문 preset을 위 표처럼 높였다. 료칸 천장 공유 높이는 11.5m, 입장 위치는 중앙 보행홀의 (400, 5.3)이다. 입구 남쪽 벽 때문에 넓은 거리 요청이 실제로 줄어들지 않도록 기존 z8.5에서 3.2m 안쪽으로 옮겼다. 문과 외관 위치는 유지한다. 실내 재입장·시설 이용은 이 preset을 반복 적용하지 않는다. 상세 근거와 좌석 선택 변경은 `seating-and-indoor-view-v44.md`에 기록한다.
- 캐릭터가 실내 벽에 아주 가까우면 focus를 내부 안전 여유 안으로 조금 보정한다. 방 벽, 천장, 천문대 곡면 지붕은 **같은 시선 방향을 유지하며 거리만 줄이는 방식**으로 처리한다.
- 기존 실제 mesh 충돌, 태그가 붙은 리프트 지지대·관람차 패널의 일시적인 fade를 유지한다. 시설 mode 변경은 충돌 복구 거리를 초기화하지 않는다. 장애물에서 벗어났을 때의 거리 회복 속도는 초당 3.5 이하로 제한한다. 방·지형 검사에서 먼저 줄인 거리를 이후 검사에서 다시 늘리지 않는다.

### 스키 예외

수동으로 yaw를 바꾼 적이 없다면 스키 진행 방향을 뒤에서 보는 yaw 추적을 허용한다. 각도 변화 속도는 초당 1.6 rad 이하이며, pitch·zoom·FOV는 속도에 따라 바뀌지 않는다. 수동 좌우 회전을 하면 자동 yaw 추적이 꺼진다. 수직 조절과 줌은 그대로 적용된다. 자동 추적 상태에서 내리면 마지막 시선 방향을 보존하여 원래 방향으로 갑자기 회전하지 않는다.

스키 초점은 캐릭터 중심에 둔다. 앞쪽으로 초점을 이동시키면 급경사 충돌로 카메라가 가까워질 때 카메라가 오히려 캐릭터 앞쪽에 놓일 수 있어 look-ahead 이동을 제거했다. 조향 방식과 스키 물리 코드는 변경하지 않는다.

## 트리 장식

트리 전체를 화면에 맞추던 강제 원거리 시점은 제거했다. 현재 yaw·pitch를 유지하며 캐릭터에 가까운 낮은 수관의 6m 높이 지점으로 초점을 부드럽게 옮긴다. 임시 거리 증가량은 요청 거리의 16%, 최대 3m다. 기본 상태의 장식 거리 요청은 19.14m다.

닫으면 임시 거리 증가만 제거한다. 장식 중 사용자가 직접 바꾼 각도와 거리는 남긴다. 수동 줌을 시작하면 그 시점의 렌더 거리를 요청값에 반영하여 잠깐 늘었던 거리와 이중으로 합산하지 않는다. 걷기, 시설 이용, 실내 이동은 장식 프레이밍을 종료한다. reduced motion에서는 자동 트리 프레이밍을 생략한다.

## 변경 파일

- `dist/camera-policy.js`: 요청 시야, 수동 조절, 방별 시야, 시설 예외, focus와 거리 경계 함수.
- `dist/park.js`: 카메라 writer 통합, 시점 전환·입력 hook, 고정 FOV, 점프 분리. 기존 식사 시작 시각과 서버 시각 전달 및 성능 UI 제거를 유지한다.
- `dist/activity-camera.js`: 활동 시작으로 카메라 preset을 강제하지 않는 메타데이터.
- `dist/camera-clearance.js`: mode 전환 시 거리 복구 보존 및 앞선 안전 거리 제한 존중.
- `tests/camera-policy.test.mjs`, `tests/camera-clearance.test.mjs`, `tests/runtime.test.mjs`: 수치·충돌·앱 통합 회귀.
- 입력 UI와 `game-input.js`는 협업 변경이며 `camera-controls.js/css`를 통해 연결된다.

## 검증 및 한계

2026-11-18의 초기 카메라 안정화 focused 실행은 **48개 통과, 실패 0개**다. `park.js`, `camera-policy.js` 구문 검사와 `git diff --check`도 통과했다. 이후 실내 preset과 좌석 선택의 추가 검증은 `seating-and-indoor-view-v44.md`에 별도로 기록한다.

정책·충돌 수치 검증은 점프 초점 고정, 말 bob 상쇄, 시설과 제스처의 수동값 보존, 트리 닫기 후 최신 수동값 보존, 방별 snapshot, 스키 yaw 예외와 고정 FOV, 평지의 낮은 시야, 실내 벽·곡면 천장의 시선 방향 보존을 포함한다. 실제 앱 DOM/Three scene 통합 검증은 stub renderer를 사용한다. 일반 휠 무시와 조절 모드 휠, 점프, resize, 리프트·스키, 온천, 실내 입출구, 관람차와 회전목마, 기본 시야 복귀를 확인한다.

```sh
node --experimental-vm-modules --test tests/camera-policy.test.mjs tests/camera-clearance.test.mjs tests/camera-raycast.test.mjs tests/runtime.test.mjs tests/shared-rides.test.mjs tests/alpine-runs.test.mjs tests/carousel-model.test.mjs tests/winter-experience.test.mjs
```

이 환경의 Chromium은 WebGL 생성이 실패하고 GL renderer가 비활성화되어 있다. 실제 GPU 화면의 구도, 기기별 체감 멀미, 실제 휴대폰 FPS와 장시간 렌더 성능은 **UNKNOWN**이다. 수치 검증을 실제 기기 육안 검증으로 보고하지 않는다. 카메라 충돌로 인한 거리 축소는 필요한 안전 동작이며 모든 지형에서 물리적인 카메라 거리를 완전히 고정한다고 보장하지 않는다.
